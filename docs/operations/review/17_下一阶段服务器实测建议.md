# 17_下一阶段服务器实测建议

> 本文用于把 v1.2 手册转化为可执行的服务器侧实测清单。

## 1. 真实只读环境检查

执行方：服务器/Claw/人工。

建议动作：

- 检查编译链关键依赖与版本；
- 检查磁盘、端口、进程、权限等环境前置项；
- 回传完整命令输出（含时间、主机标识）。

Codex职责：仅解读回传结果，不宣称“已在服务器执行”。

## 2. base 编译复验

执行方：服务器/Claw/人工。

建议动作：

- 在目标环境执行 `make -C base`；
- 保存完整日志（从命令开始到结束）；
- 标记首个报错点。

Codex职责：基于日志定位根因并给最小补丁建议。

## 3. 主服务编译复验

执行方：服务器/Claw/人工。

建议动作：

- 按 Makefile 链路进行主服务编译复验；
- 区分依赖缺失、链接失败、脚本路径错误等类别；
- 回传模块级失败日志。

Codex职责：做静态诊断与修复建议，不执行编译。

## 4. 启动链路联调

执行方：服务器/Claw/人工。

建议动作：

- 在 A/B 基线中选择一套启动顺序并执行；
- 记录进程状态、日志路径、失败断点；
- 停服优先温和策略，`kill -9` 仅兜底。

Codex职责：根据脚本与日志比对定位问题。

## 5. 客户端/登录器联调

执行方：服务器/Claw/人工。

建议动作：

- 验证客户端到登录器到网关到场景服链路；
- 记录成功路径与失败路径；
- 回传关键日志片段与时间线。

Codex职责：只做链路问题分析与文档更新建议。

## 6. Codex 只接收日志并分析补丁

协作约束：

- Codex 不执行编译、不启动服务、不连接数据库；
- Codex 仅基于仓库文件与服务器回传日志输出：
  1) 首错定位；
  2) 候选根因；
  3) 最小补丁建议；
  4) 人工复核清单。

## 7. 建议交付节奏

1. 服务器侧完成“只读环境检查”并回传；
2. 服务器侧完成“base 编译复验”并回传；
3. 服务器侧完成“主服务编译 + 启动联调”并回传；
4. Codex 分阶段给出诊断与补丁建议；
5. 人工确认后再进入变更实施。
