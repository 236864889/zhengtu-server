## 第 1 章：手册定位与适用范围

### 1.1 适用项目
- 适用于本仓库 `ztgame/` 相关服务端源码的编译、配置、启动与联调流程。
- 适用于“可审计、可回滚、可交接给 Codex/Claw”的标准化运维流程。

### 1.2 适用环境
- Linux 服务端环境（历史教程以 CentOS 6.5 为基线；当前环境版本按实际主机“待确认”）。
- 具备 shell、make、g++、mysql_config、xml2-config 可用能力的主机环境。

### 1.3 不适用范围
- 不含破解、私服外网映射、未知补丁注入、协议逆向实战步骤。
- 不含登录器二进制逆向改造细节。
- 不含 Qdrant/Embedding/RAG 入库执行流程（本轮继续暂停）。

### 1.4 本手册与历史教程关系
- `docs/rag_sources/` 和仓库脚本是“当前主线”。
- `教程系列_上传版/` 仅作为历史线索；不直接当作 SOP。

### 1.5 本手册与 RAG 入库关系
- 本手册只做操作规范化输出；不执行向量化入库。
- 后续如恢复 RAG，须以本手册章节为索引来源。

## 第 2 章：环境准备

### 2.1 操作系统基线
- 历史基线：CentOS 6.5（来自历史教程）。
- 当前主线：Linux 可编译环境，具体发行版“待确认”。

### 2.2 root/普通用户策略
- 编译建议使用普通用户；仅依赖安装和系统目录授权使用 root。
- 成功判定：普通用户可读写源码目录、日志目录、备份目录。
- 回滚建议：若权限异常，撤销临时 `chmod -R 777` 类高风险授权，改为最小权限。

### 2.3 目录规划
- 源码目录：`/workspace/zhengtu-server/ztgame`（示例：当前仓库路径）。
- 备份目录：`/data/backup/zhengtu/`（待确认，可替换为企业标准目录）。
- 日志目录：以服务默认日志路径为准（`/tmp/*.log*` 现象已见，长期日志目录待确认）。

### 2.4 磁盘与网络条件
- 磁盘：保证源码、编译中间产物、日志、备份的可用空间（阈值待确认）。
- 网络：至少保障服务间内网互通与数据库可达。
- 成功判定：`df -h` 无高危分区爆满；`ip a` 与目标 IP 规划一致。

## 第 4 章：源码目录说明

- `base`：基础库（网络、日志、DB 封装等）。
- `SessionServer`：会话服务。
- `GatewayServer`：网关与连接侧。
- `ScenesServer`：场景逻辑（含 Lua/luabind 依赖）。
- `RecordServer`：记录类服务。
- `BillServer`：计费/账务相关服务。
- `SuperServer`：核心调度/总控角色之一。
- `FLServer`：登录链路相关服务。
- `MiniServer`：轻量业务服务节点。
- `Config`：玩法/系统 XML 配置。
- `script`：Lua、luabind 静态库来源。
- `newquest`、`quest`：任务脚本与配置。
- `tools`：工具程序（如 `zntop` 等）。
- `ztgame.dat / 登录器`：客户端与登录器联调对象，不在本手册中做逆向修改。

成功判定：目录与职责映射可用于排障分层，且与 `Makefile/SUB_DIRS` 一致。

## 第 5 章：base 编译

> 本章给出操作规范，不在本轮执行。

### 5.1 为什么先编 base
- 多服务统一依赖 `base` 静态库，先通过可减少后续链式报错。

### 5.2 标准命令（供后续执行）
```bash
make -C base
```

### 5.3 关键产物
- `libzebra.a`
- `libencdec.a`
- `libcrypto.a`

### 5.4 常见错误
- 头文件/模板兼容问题。
- log4cxx 版本兼容问题。
- socket/DB pool 历史语法兼容问题。

### 5.5 成功/失败判定
- 成功：上述静态库生成且时间戳更新。
- 失败：make 返回非 0，或静态库缺失。
- 回滚建议：保留失败日志，恢复到上一个可编译提交，不直接覆盖库文件。

## 第 6 章：主服务编译

### 6.1 顶层构建命令（供后续执行）
```bash
make
```

### 6.2 编译顺序与产物
- 顺序参照 `ztgame/Makefile`：`base/EncDec -> base -> MiniServer -> ScenesServer -> SessionServer -> BillServer -> GatewayServer -> SuperServer -> RecordServer -> FLServer -> tools`。
- 关键服务产物：`MiniServer/MiniServer`、`ScenesServer/ScenesServer`、`SessionServer/SessionServer`、`BillServer/BillServer`、`GatewayServer/GatewayServer`、`SuperServer/SuperServer`、`RecordServer/RecordServer`、`FLServer/FLServer`。

### 6.3 依赖关系重点
- 通用依赖：`-lzebra -lencdec`。
- `ScenesServer` 重点：`-llua -lluabind` 链接链路。

### 6.4 常见错误与判定
- 依赖库缺失、链接失败、符号未定义。
- 成功：所有目标二进制生成。
- 失败：某模块终止，记录首个报错并定位到模块 Makefile/依赖。

## 第 8 章：数据库准备

```bash

mysql -h <host> -u <user> -p -e "SHOW TABLES FROM <db_name>;"
```

### 8.4 约束
- 手册禁止给出危险 `UPDATE/DELETE` 操作模板。
- 成功判定：连通正常、库表存在、字符集符合预期。

## 第 9 章：服务启动顺序

### 9.1 启动顺序基线
- `start.sh`：`SuperServer -> RecordServer -> BillServer -> MiniServer -> SessionServer -> ScenesServer -> GatewayServer`（`FLServer` 注释）。
- `start1.sh`：`SuperServer -> FLServer -> RecordServer -> BillServer -> MiniServer -> SessionServer -> ScenesServer -> GatewayServer`。
- 推荐验证顺序（含待确认历史组件）：`FLServer -> UserServer -> SuperServer -> RecordServer -> BillServer -> MiniServer -> SessionServer -> ScenesServer -> GatewayServer`。

### 9.2 UserServer 说明
- 仓库未见 `UserServer/` 目录，属于“历史术语或外部组件待确认”。

### 9.3 停服脚本
- `stop.sh` 使用 `kill -9`，存在强停风险。
- 回滚建议：优先温和停服（若后续补齐脚本），`kill -9` 仅应急使用。

### 9.4 每步启动后日志检查
- 检查最近日志是否有 `error/fail/refused/segmentation` 关键字。
- 成功判定：当前服务存活且下游可继续启动。

## 第 12 章：常见错误与解决方法

> 每条统一格式：错误现象 / 常见原因 / 检查命令 / 修复建议 / 是否人工复核。

1. 编译错误（通用）
- 现象：make 中断。
- 原因：依赖缺失、头文件冲突、编译器兼容。
- 检查：`make 2>&1 | tee build.log`。
- 建议：先修首个错误，勿并发改动。
- 人工复核：是。

2. log4cxx 错误
- 检查：`ldconfig -p | grep log4cxx`。
- 建议：按已修复记录对齐兼容方案。
- 人工复核：是。

3. Lua/luabind 错误（ScenesServer）
- 检查：`ls script/*.a`、`grep -n 'llua\|lluabind' ScenesServer/Makefile`。
- 建议：确认静态库存在且链接顺序正确。
- 人工复核：是。

4. MySQL 连接错误
- 检查：`mysql -h <host> -u <user> -p -e 'select 1;'`。
- 建议：核对账号、白名单、字符集。
- 人工复核：是。

5. XML 缺失/配置错误
- 检查：`find Config -maxdepth 2 -name '*.xml' | sort`。
- 建议：从备份回滚完整配置集。
- 人工复核：是。

6. 端口占用/启动即退出/场景服初始化失败/客户端登录失败
- 检查：进程、端口、日志三联查。
- 建议：先定位首个失败服务，再排下游连锁报错。
- 人工复核：是。
