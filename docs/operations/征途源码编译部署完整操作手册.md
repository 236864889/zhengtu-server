# 征途源码编译部署完整操作手册 v1.1

> 适用范围：仅用于 `zhengtu-server` 仓库内“文档化 SOP 维护与复核”。
> 本版为 v1.1 补齐修订版，不执行编译/启动/停服动作。

## 0. 来源路径可用性检查

执行手册前先做只读检查并记录结果：

- `docs/rag_sources/`
- `docs/source_analysis/tutorials_inventory/`
- `docs/source_analysis/ztgame_dat/runtime_validation/`
- `docs/source_analysis/launcher_reanalysis/`

- `ztgame/start1.sh`
- `ztgame/stop.sh`
- `教程系列_上传版/`（可选历史来源，缺失不阻断）

规则：

1. 主线来源（上方除“教程系列_上传版/”外）缺失时，不应继续执行手册主流程。
2. 历史来源 `教程系列_上传版/` 缺失不阻断，但必须记录“来源缺失/待补齐”。
3. 所有缺失来源必须写入当轮复核记录。

## 1. 文档基线与证据优先级

1. S/A 级证据优先：`docs/rag_sources/01/02/03/05/06/08/09/10` 与仓库脚本。
2. `ztgame/Makefile`、`start.sh`、`start1.sh`、`stop.sh` 为顺序与风险事实基线。
3. C/D 级历史教程仅可作背景，不得写入正式 SOP 主流程。
4. 破解类、不可验证类内容明确排除。

## 2. 编译链路（事实基线，仅记录不执行）

以 `ztgame/Makefile` 的 `SUB_DIRS` 为准：

`base/EncDec -> base -> MiniServer -> ScenesServer -> SessionServer -> BillServer -> GatewayServer -> SuperServer -> RecordServer -> FLServer -> tools`

补充说明：

- `script` 不是顶层 `SUB_DIRS`，但 `ScenesServer` 等模块会链接 `script/liblua.a`、`script/libluabind.a`、`script/liblualib.a` 等静态库。
- 编译产物核对重点：`libencdec.a`、`libzebra.a`、`libcrypto.a`、各 Server 二进制、`tools` 产物。

## 3. 启动顺序双基线（事实并列，不混写）

### 基线A：`start.sh`

`Super -> Record -> Bill -> Mini -> Session -> Scenes -> Gateway`

- `FLServer` 默认注释，不启动。

### 基线B：`start1.sh`

`Super -> FL -> Record -> Bill -> Mini -> Session -> Scenes -> Gateway`

- `FLServer` 默认启动。

使用要求：

1. 上线前必须先确定正式 SOP 采用 A 还是 B。
2. 文档、脚本、值班手册必须保持同一基线。

## 4. UserServer 状态说明（必须人工确认）

- 当前源码树未见 `ztgame/UserServer/` 目录。
- `UserServer` 可能是历史术语、部署外部组件或旧版本组件。
- 不得在正式 SOP 中写成必然步骤。
- 上线前必须确认是否需要外部 `UserServer`。

## 5. stop.sh 停服风险提示

- `stop.sh` 存在 `kill -9` 强停风险。
- 生产环境优先温和停服。
- `kill -9` 只能作为兜底。
- 执行前必须确认 PID，避免误杀。

## 6. 配置、数据库与网络检查（只读）

- 配置侧：`Config/*.xml` 与根目录 `*.xml`、`quest/`、`newquest/` 的路径与可读性。
- 数据库侧：连接参数来源、库名表名权威来源（配置文件/初始化 SQL/运维文档）。
- 网络侧：端口与拓扑在仓库中未完全固化，需由运维基线文档补充。

## 7. 常见故障处理总则

1. 先定位阶段：依赖缺失 / base 编译 / ScenesServer 链接 / 启动后退出 / 登录失败。
2. 先查事实文件，再决定处理：`Makefile`、服务目录日志、`docs/rag_sources/10_已修复编译问题记录.md`。
3. `base` 与 `ScenesServer` 问题优先按附录B关键词表排查。

## 8. 历史教程降级策略

- `教程系列_上传版/` 中 C/D 级历史文档不得进入正式 SOP 主流程。
- B 级仅抽取“事实线索”，不照搬命令。
- 破解类、不可验证类内容明确排除并隔离到历史参考。

## 9. 上线前检查（P0/P1 收口）

### P0（发布前必须确认）

1. 当前正式 OS 基线版本（CentOS 6.5 是历史基线还是现行基线）。
2. 生产端口号与完整拓扑（外网入口、内网互联、数据库访问域）。
3. `UserServer` 是否仍为部署必需组件。
4. 服务日志实际落盘目录（含 `/tmp/*.log*` 行为是否仍存在）。
5. 数据库库名/表名最终权威来源。
6. `gd` / `jpeg` 在当前构建链是否仍为必需。
7. 启动顺序最终采用 `start.sh` 还是 `start1.sh`。

### P1（v1.1 建议确认）

1. 部署态二进制目录与源码目录差异（`./SuperServer` vs `SuperServer/SuperServer`）。
2. `roleRegServer`、`InfoServer` 在现网是否仍保留。
3. 客户端/登录器联调中 `runtime_validation` 与 `launcher_reanalysis` 的优先级顺序。
