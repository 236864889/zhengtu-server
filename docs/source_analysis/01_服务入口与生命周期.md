# 征途服务端源码深度分析：服务入口与生命周期

## 范围
- 目录：`ztgame/BillServer`、`FLServer`、`GatewayServer`、`MiniServer`、`RecordServer`、`ScenesServer`、`SessionServer`、`SuperServer`。
- 目标：定位 `main/init/final/validate` 入口，并提取可用于 RAG 的事实。

## 1) main 入口（已定位）
- `BillServer.cpp:369`、`FLServer.cpp:322`、`GatewayServer.cpp:494`、`MiniServer.cpp:294`、`RecordServer.cpp:284`、`ScenesServer.cpp:842`、`SessionServer.cpp:859`、`SuperServer.cpp:378` 均存在 `int main(...)`。

## 2) init/final 入口（服务对象）
- Bill：`BillService::init` / `BillService::final`。
- FL：`FLService::init` / `FLService::final`。
- Gateway：`GatewayService::init` / `GatewayService::final`。
- Mini：`MiniService::init` / `MiniService::final`。
- Record：`RecordService::init` / `RecordService::final`。
- Scenes：`ScenesService::init` / `ScenesService::final`。
- Session：`SessionService::init` / `SessionService::final`。
- Super：`SuperService::init` / `SuperService::final`。

## 3) validate 入口线索
- 基类 `zService` 定义了 `validate()` 接口；`zSubNetService` 也实现了 `validate()` 流程。
- Gateway 服务头文件显式覆写 `validate()` 并调用 `zSubNetService::validate()`。
- 工具侧 `zebraclientService` 也存在 `validate()` 调用链（用于测试/压测，不属于业务服务主链）。

## 4) 服务初始化差异（关键事实）
- `ScenesService::init` 中包含大量玩法配置初始化调用（`fjconfig::init*`、`NpcTrade::init`、`MallTrade::init`、`MessageSystem::init`、`MagicRangeInit::init` 等），其初始化复杂度最高。
- `SuperService::init` 明确初始化 `FLClientManager`、`RoleregClientManager`、`InfoClientManager`，并调用 `zNetService::init(wdPort)`。
- `FLService::init` 明确依赖 `DBAccessClientManager::init()` 与 `InfoClientManager::init()`。

## 5) 待确认
- 各服务 `main` 中对 `validate()` 的触发时机和失败返回码路径需逐个函数内继续核查（建议下一阶段补充函数级调用图）。
