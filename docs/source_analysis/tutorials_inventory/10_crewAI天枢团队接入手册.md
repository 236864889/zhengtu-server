# crewAI 天枢团队接入手册（交接版）

> 目的：让后续 crewAI 天枢团队在不反复沟通的前提下，正确接手并持续推进改造工作。

## 1. 项目背景与当前状态

当前仓库由四大资产域组成：

1. `教程系列_上传版`（历史教程资料）
2. `配套官网`（注册/充值/抽奖/找回）
3. `登录器`（C# WinForms 启动器）
4. `mysql`（核心数据库脚本）

已完成内容（可作为交接起点）：

- 资料盘点：`07_教程系列_上传版全量盘点总结.md`
- 全栈深度分析：`08_教程系列与官网登录器MySQL全景深度分析.md`
- 30天治理路线图：`09_治理执行计划_30天路线图.md`
- 官网密钥外置：`配套官网/db.php` + `.env.example`
- 支付验签工具与回归样例：`配套官网/scripts/epay_sign.php`、`配套官网/tests/payment_notify_cases.md`

---

## 2. 天枢团队工作目标（必须对齐）

## 2.1 总目标

- **安全**：仓库内不出现生产凭据；支付回调可验证且可回归。
- **稳定**：注册、充值、抽奖、找回全链可回归。
- **可维护**：教程从历史散文转成 SOP；关键链路可观察可交接。

## 2.2 里程碑目标

- M1：完成 P0（安全止血 + 支付回归 + 口令机制核验）
- M2：完成 P1（编码治理蓝图 + 官网公共层 + 登录器分层初版）
- M3：完成 P2（教程SOP首批 + E2E发布清单上线）

---

## 3. 角色分工建议（crewAI 多Agent）

建议按 5 个 Agent 并行：

1. **Security Agent**
   - 负责凭据扫描、配置外置、敏感信息治理。
2. **Payment Agent**
   - 负责 `recharge_compat.php` / `epay_notify.php` 联调与回归。
3. **Data Agent**
   - 负责 MySQL 表结构对齐、编码策略、对账核验。
4. **Launcher Agent**
   - 负责 `登录器` 远程 JSON 耦合治理与分层改造。
5. **Docs Agent**
   - 负责教程SOP化、发布清单与文档质量门禁。

> 每个 Agent 必须输出“可执行产物”（脚本/文档/检查结果），不能只给结论。

---

## 4. 标准工作流（每个任务都遵守）

1. **任务声明**：目标、影响范围、风险、回滚方案。
2. **证据收集**：列出引用文件、命令输出、关键日志。
3. **最小改动**：优先局部修改，避免跨域大爆炸。
4. **验证闭环**：至少一条功能验证 + 一条回归验证。
5. **交付记录**：输出变更摘要、待办、阻塞项。

---

## 5. 任务优先级队列（给 crewAI 直接消费）

## P0（立即做）

1. 凭据治理复查：全仓库再次扫描敏感信息。
2. 支付回调回归落地：执行 `payment_notify_cases.md` 四大场景。
3. 口令机制核验：确认 `PASSWD` 字段真实机制与迁移可能性。

## P1（短期）

1. 编码策略台账：latin1/gbk/utf8mb4 使用矩阵。
2. 官网公共层抽离：连接、响应、限流、日志脱敏统一。
3. 登录器分层：UI / 配置 / 更新执行拆分。

## P2（中期）

1. 教程SOP化（Top30高频主题）。
2. 发布前 E2E 清单制度化（注册->登录->充值->到账->抽奖->对账）。

---

## 6. 质量门禁（Definition of Done）

任何任务完成都必须满足：

1. **可复现**：有命令或脚本可重跑。
2. **可验证**：有预期结果与实际结果。
3. **可回滚**：有失败回退步骤。
4. **可追踪**：有文件路径与变更记录。
5. **无泄露**：不含真实生产凭据。

---

## 7. 必交付文档清单（天枢团队）

每周至少产出：

1. 《周进展报告》：完成项/风险项/下周计划
2. 《回归结果清单》：场景、命令、结果、截图或日志
3. 《风险台账》：风险等级、影响面、负责人、预计关闭时间
4. 《变更索引》：PR/Commit 与对应任务映射

---

## 8. 推荐协作节奏

- 每日：15 分钟站会（阻塞项优先）
- 每周：一次里程碑评审（按 M1/M2/M3）
- 每次发布前：执行 E2E 清单并冻结高风险改动

---

## 9. 对天枢团队的执行要求（硬约束）

1. 先证据，后结论。
2. 先小步，后重构。
3. 先验签与对账，后功能扩展。
4. 先SOP沉淀，后经验传播。

只要严格执行以上约束，后续交接、扩编和自动化协作会非常顺畅。
