# 任务脚本源码走读模板（quest / newquest / script 三层映射）

> 目的：让天枢团队针对任务系统做“可复制、可验收”的深度读码。  
> 范围：仅提供走读模板与映射方法，不改动业务逻辑。

## 1. 为什么要做三层映射

任务系统的实现通常跨 3 层：

1. `quest/`：任务定义与流程主干
2. `newquest/`：新版本或扩展任务逻辑
3. `script/`：动作执行与细节控制

如果只看其中一层，容易出现：
- 只看到任务描述，看不到执行动作
- 只看到脚本动作，不知道何时被触发
- 只看到场景事件，不知道最终奖励如何落地

## 3. 推荐走读顺序（单任务）

1. 先在 `quest/` 找任务入口与状态定义。
2. 再在 `newquest/` 找是否存在扩展或覆盖逻辑。
3. 最后在 `script/` 找动作执行细节（奖励、NPC对话、分支处理）。
4. 回到 `ScenesServer` 核对触发来源与状态更新时机。

---

## 4. 三个必做样本（首轮）

1. 新手任务（主线开局）
2. 日常任务（可重复）
3. 活动任务（时效或条件复杂）

每个样本都要完整填完第 2 节模板，不得只写结论。

---

## 5. 常见误区（避免）

1. 只记录任务名称，不记录任务ID与状态值。
2. 只写成功路径，不写失败分支。
3. 只写奖励类型，不写落账位置。
4. 不做复现实验，导致无法验证理解正确性。

---

## 6. 验收标准（天枢团队）

达到以下条件才算“任务脚本熟悉完成”：

1. 至少 3 条任务链完成三层映射。
2. 每条任务链有状态推进表。
3. 每条任务链有奖励落账映射。
4. 每条任务链有复现实验记录。
5. 能说明一个异常分支的恢复路径。
