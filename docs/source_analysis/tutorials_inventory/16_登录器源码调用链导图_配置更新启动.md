# 登录器源码调用链导图（配置 / 更新 / 启动）

> 目的：帮助天枢团队快速看懂 `登录器/WindowsFormsApplication1` 的关键逻辑链。  
> 范围：仅做源码认知导图，不改动业务逻辑。

## 1. 登录器总链路（全景）

```text
程序启动(Program.cs)
  -> 主窗体初始化(Form1/title)
    -> 拉取远程 JSON 配置
      -> 解析区服/页面链接/更新项
        -> 自更新检查（登录器自身）
          -> 客户端文件更新检查
            -> 写入/更新 config.ini
              -> 启动游戏进程
```

核心阅读文件：

- `登录器/WindowsFormsApplication1/Program.cs`
- `登录器/WindowsFormsApplication1/Form1.cs`
- `登录器/WindowsFormsApplication1/BrowserEmulation.cs`

---

## 2. 配置链路（JSON -> 内存对象 -> UI）

## 2.1 关注点

1. JSON 地址在哪里定义。
2. 失败重试或异常处理如何做。
3. 区服分组、区服节点如何绑定到 UI 控件。
4. 官网页面链接（注册/充值/公告）如何下发并打开。

## 2.2 走读建议

- 先找 `Form_Load` 入口。
- 再看“配置下载 -> 解析 -> 绑定控件”的调用顺序。
- 最后看配置缺失/字段异常时 UI 表现。

---

## 3. 更新链路（自更新 + 游戏更新）

## 3.1 自更新链

```text
读取 JSON 的自更新字段
  -> 对比本地 EXE 校验值
    -> 需要更新则下载 ZIP
      -> 解压并替换
        -> 重启或继续流程
```

## 3.2 游戏更新链

```text
读取 JSON 更新列表
  -> 逐项校验本地文件 MD5
    -> 不一致则下载补丁包
      -> 解压覆盖目标路径
        -> 再校验/记录日志
```

## 3.3 阅读检查点

1. 更新失败是否阻断启动。
2. 部分文件更新失败是否可降级。
3. 更新日志是否足够定位问题。
4. ZIP 解压与覆盖过程是否有安全边界检查（路径穿越等）。

---

## 4. 启动链路（区服选择 -> 写配置 -> 启动游戏）

## 4.1 典型链路

```text
用户选择区服
  -> 读取区服 IP/Port/Zone
    -> 写入 config.ini
      -> 启动 ztgame.dat / ztgame.exe
```

## 4.2 阅读检查点

1. 未选择区服时是否拦截启动。
2. 写 `config.ini` 失败时是否有提示。
3. 启动目标文件选择优先级是否明确。
4. 防重复启动逻辑是否有效。
