# 天枢团队源码深度认知导读（仅聚焦源码熟悉）

> 本文只做一件事：帮助天枢团队更快、更准确地熟悉核心源码文件与逻辑链路。  
> 不讨论治理排期，不扩展到运营流程。

## 1. 阅读目标（先统一）

天枢团队在源码熟悉阶段的目标应是：

1. 看懂服务端多进程边界。
2. 看懂客户端入口与更新链路。
3. 看懂 `ztgame.dat` 中“引擎/渲染/UI/脚本绑定”关系。
4. 能独立画出“登录 -> 进场景 -> 任务 -> 奖励”的主调用链。

---

## 2. 建议阅读顺序（强制顺序）

## 第 0 层：先看目录地图（30~60 分钟）

1. `ztgame/`：服务端主工程目录。
2. `ztgame.dat/`：客户端+引擎+资源流程目录。
3. `登录器/WindowsFormsApplication1/`：入口启动器。

目标：先知道“模块在哪”，不要一上来钻函数细节。

## 第 1 层：入口链路（半天）

### A. 登录器入口
- `登录器/WindowsFormsApplication1/Program.cs`
- `登录器/WindowsFormsApplication1/Form1.cs`

先看：程序启动、JSON配置拉取、区服选择、更新检查、启动游戏。

### B. 服务端入口
- `ztgame/start.sh`
- `ztgame/start1.sh`
- `ztgame/Config/` 下的关键配置

先看：服务启动顺序与依赖关系。

## 第 2 层：服务端核心（2~4 天）

按“从公共层到业务层”阅读：

1. `ztgame/base/`（公共基础设施）
2. `ztgame/SessionServer/`（会话/登录态）
3. `ztgame/GatewayServer/`（网关入口）
4. `ztgame/ScenesServer/`（场景与玩法主承载）
5. `ztgame/BillServer/`、`RecordServer/`（计费/记录链路）

阅读时只回答三件事：
- 这个服务接收什么输入？
- 把数据交给谁？
- 最终落到哪个表/哪个脚本逻辑？

## 第 3 层：任务脚本体系（2~3 天）

重点目录：

- `ztgame/quest/`
- `ztgame/newquest/`
- `ztgame/script/`

目标：识别任务状态推进、奖励发放、异常分支。  
要求：至少完整走读 3 条任务链（新手任务/日常任务/活动任务）。

## 第 4 层：客户端与引擎（2~4 天）

重点目录：

- `ztgame.dat/Client/`
- `ztgame.dat/engine/`
- `ztgame.dat/RenderD3D/`
- `ztgame.dat/gui/`
- `ztgame.dat/Magic/`

目标：看懂“表现层”如何与服务端状态对应，尤其是：
- 技能特效触发
- UI事件与网络状态刷新
- 场景加载与资源依赖

## 3. 源码阅读输出标准（每天必须产出）

每天必须提交 1 份“源码认知卡片”：

1. 今天阅读的目录/文件。
2. 关键函数/类（不超过 10 个）。
3. 调用方向（谁调用谁）。
4. 仍不确定的问题列表。
5. 一条可复现验证命令或运行步骤。

> 没有“认知卡片”的阅读视为无效阅读。

---

## 4. 天枢团队最容易跑偏的点（提前规避）

1. **只看文档不看代码**：必须回到具体文件。
2. **只看单个服务**：必须串起来看跨服务调用。
3. **忽略脚本目录**：任务逻辑大量在脚本，不在 C++ 主流程里全写死。
4. **客户端与服务端割裂看**：要用“同一业务场景”对照两边实现。

---

## 5. 建议的“最小深度认知验收”

满足以下 5 条才算“熟悉源码”：

1. 能画出登录链路的服务调用图。
2. 能定位一条任务从接取到发奖涉及的文件集合。
3. 能说明一个客户端UI动作如何触发服务端状态变化。
4. 能定位充值到账后对玩家点数/日志的影响路径。
5. 能独立列出 10 个高风险改动点（并给理由）。
