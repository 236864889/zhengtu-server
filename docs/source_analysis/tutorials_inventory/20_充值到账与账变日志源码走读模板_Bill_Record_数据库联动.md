> 目的：帮助天枢团队深度掌握“充值到账 -> 点数变化 -> 日志落库”的高风险链路。  
> 范围：源码走读模板，不改业务逻辑。

## 1. 业务主链路（总览）

```text
外部充值请求/回调
  -> 业务入口处理
    -> 账务服务（Bill）
      -> 记录服务（Record）
        -> 数据库更新（订单/点数/流水）
          -> 客户端或后台可见结果
```

重点：到账正确性、幂等、可追溯。

## 3. 推荐走读顺序

1. 先看回调入口与签名校验。
2. 再看订单状态校验与锁/事务处理。
3. 再看点数变更与流水记录写入顺序。
4. 最后看响应返回与失败分支。

---

## 4. 必做样本（首轮）

1. 正常到账（首次回调）
2. 重复回调（幂等验证）
3. 错签回调（拒绝验证）
4. 超时回调（时窗验证）

每个样本都要有 SQL 核对与结果证据。

---

## 5. 常见误区（避免）

1. 只看返回文本，不核对数据库状态。
2. 只看订单状态，不核对点数与流水一致性。
3. 忽略并发场景（两次回调几乎同时到达）。
4. 只看成功路径，不看回滚路径。
