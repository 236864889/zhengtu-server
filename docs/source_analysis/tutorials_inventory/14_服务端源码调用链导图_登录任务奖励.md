# 服务端源码调用链导图（登录 / 任务 / 奖励）

> 目的：仅用于天枢团队“读源码时的导航”，帮助快速建立跨服务调用链认知。  
> 注意：本文件是导图与阅读路径，不替代实际代码走读。

## 1. 登录主链（建议先走通）

```text
登录器(客户端入口)
  -> GatewayServer（连接接入/初步分发）
    -> SessionServer（账号会话、登录态）
      -> ScenesServer（角色进场景）
        -> quest/newquest/script（上线触发任务/状态）
```

### 1.1 建议定位目录

- `ztgame/GatewayServer/`
- `ztgame/SessionServer/`
- `ztgame/ScenesServer/`
- `ztgame/quest/`、`ztgame/newquest/`、`ztgame/script/`

### 1.2 阅读检查点

1. 登录请求在哪个服务首次落地。
2. 会话校验在哪个服务完成。
3. 角色“进图”状态由谁最终确认。
4. 上线后是否触发任务脚本/奖励脚本。

---

## 2. 任务主链（任务接取 -> 状态推进 -> 任务完成）

```text
ScenesServer（玩法事件触发）
  -> quest/newquest（任务条件判定）
    -> script（脚本动作执行）
      -> 奖励发放逻辑（经验/物品/点数等）
        -> 记录/落账（Record/Bill/数据库）
```

### 2.1 建议定位目录

- `ztgame/ScenesServer/`
- `ztgame/quest/`
- `ztgame/newquest/`
- `ztgame/script/`
- `ztgame/RecordServer/`
- `ztgame/BillServer/`

### 2.2 阅读检查点

1. 任务条件由配置驱动还是代码硬编码。
2. 任务状态机在哪维护（接取、进行中、完成、失败）。
3. 奖励动作是否统一入口，是否可追踪。
4. 异常分支（背包满、条件不满足）在哪里处理。

---

## 3. 奖励主链（发奖 -> 记账 -> 可追溯）

```text
任务/活动事件
  -> 业务服务（通常在 ScenesServer 触发）
    -> 奖励计算/发放
      -> 账变记录（RecordServer / BillServer）
        -> 数据库表更新
```

### 3.1 建议核对点

1. 发奖与记账是否同事务语义（至少逻辑一致）。
2. 重复触发是否幂等（避免重复发奖）。
3. 日志能否回放“谁、何时、因何发奖”。

---

## 4. 天枢团队源码走读任务单（最小集）

## Task A：登录链路

- 输出：`登录链路图 + 关键文件清单 + 关键函数清单`
- 验收：能解释“从连接到进场景”的每一步交接点。

## Task B：任务链路

- 输出：`3条任务链样本（新手/日常/活动）`
- 验收：每条链都能定位触发点、状态推进点、完成判定点。

## Task C：奖励链路

- 输出：`奖励发放与记录映射表`
- 验收：能定位到账变表/日志表与调用入口。

---

## 5. 推荐产出格式（避免口头化）

每个 Task 的提交都应包含：

1. 目录与文件路径。
2. 函数/类名称。
3. 输入输出说明。
4. 调用上游与下游。
5. 一条可复现实验步骤（或命令）。
