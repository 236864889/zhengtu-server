# 协议与命令关键词分析（服务端）

## 覆盖关键词
- 协议头：`Command.h`、`SceneCommand.h`、`SessionCommand.h`、`RecordCommand.h`、`SuperCommand.h`、`FLCommand.h`、`BillCommand.h`、`InfoCommand.h`、`RoleregCommand.h`、`GmToolCommand.h`
- 命令路径：`Cmd::`、`stNullUserCmd`、`verifyLogin`、`verifyConn`

## 1) 协议头分层
- 公共命令头集中在 `ztgame/base/`。
- 业务 Task 文件按服务 include 对应命令头：
  - `SceneTask.cpp` -> `SceneCommand.h`
  - `SessionTask.cpp` -> `SessionCommand.h`
  - `RecordTask.cpp` -> `RecordCommand.h`
  - `BillTask.cpp` -> `BillCommand.h`
  - `SuperServer/ServerTask.cpp` -> 多命令头汇聚

## 2) 命令处理范式
1. 网络层收包后进入 `*Task`。
2. 先执行 `verifyLogin` / `verifyConn`。
3. 将缓冲区转换为 `Cmd::stNullUserCmd` 或派生结构。
4. 根据 `cmd`/`param`/子命令路由到业务处理函数。
5. 返回码与日志用于告警/追踪。

## 3) 超级服务的协议汇聚特征
- `ServerTask.cpp` 同时 include `Super/FL/RoleReg/Info/GmTool` 多协议头。
- 说明 `SuperServer` 承担跨域协调与协议桥接角色，改动风险高于单一业务服。

## 4) Session 的命令分发密度
- `SessionTask.cpp` 命令分发分支极多，覆盖社交/联盟/军团/答题/宝石等子系统。
- 对该文件的任何命令字改动都应配套做“回归矩阵”。

## 5) 建议的二开策略
- 优先新增命令而非复用旧命令字语义（避免兼容性破坏）。
- 协议结构体字段新增应保持尾部扩展，减少旧客户端风险。
- 对跨服命令统一记录 trace id，便于链路排错。
