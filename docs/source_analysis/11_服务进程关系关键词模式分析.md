# 服务进程关系关键词模式分析

## 关键词模式
- 进程入口：`main`、`*Service::init`、`*Service::final`
- 网络关系：`*Client/*ClientManager`、`verifyLogin`、`verifyConn`
- 任务关系：`*Task/*TaskManager`
- 用户对象：`*User/*UserManager`

## 1) Gateway（接入层）
- 关键词：`GateUser`、`GatewayTask`、`SceneClient`、`SessionClient`、`RecordClient`、`BillClient`
- 模式：接入客户端 -> 验证 -> 转发下游服务。

## 2) Scenes（核心玩法层）
- 关键词：`SceneUser`、`SceneNpc`、`SceneTask`、`SessionClient`、`RecordClient`、`MiniClient`
- 模式：地图/对象/战斗/任务逻辑聚合，配置与脚本初始化复杂。

## 3) Session（会话与跨子系统协调）
- 关键词：`SessionTask`、`stNullUserCmd`、`CUnion/CRelation/CCountry/...`
- 模式：单文件高密度命令路由，子系统管理器众多。

## 4) Super（跨域协调）
- 关键词：`ServerTask`、`FLClientManager`、`RoleregClientManager`、`InfoClientManager`
- 模式：多协议汇聚，承担跨服务协同。

## 5) Bill/FL/Record/Mini（专职服务）
- Bill：计费链路与账务接口。
- FL：登录与前置协调（并与 DBAccess/Info 交互）。
- Record：记录与落地。
- Mini：小游戏独立逻辑。

## 6) 共性模式（结论）
1. 每个服务都遵循 `main -> init -> task dispatch -> final`。
2. 每个服务至少存在一组 `Task + Manager`。
3. 多服务通过 `Client/ClientManager` 建立连接关系。
4. 关键风险集中在：命令分发文件、初始化长链文件、跨协议汇聚文件。

## 7) 可用于 RAG 的标签
- `process_relation` `service_entry` `task_dispatch` `cross_service_client` `high_risk_file`
