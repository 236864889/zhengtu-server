# 09_运行日志与错误排查关键词

## 范围与目标
本文件聚焦运行日志与错误排查关键词：

`ERROR / WARN / TRACE / DEBUG / INFO / PANIC / failed / 失败 / 错误 / 初始化 / 加载 / 连接 / 断开 / 关闭套接口连接 / 套接口读操作错误 / validate / final / zTCPTaskPool::final / zSubNetService::validate / zNetService::init`

目标：
1. 给出日志级别与故障语义映射；
2. 给出网络层关键函数（`init/validate/final`）排查链路；
3. 给出可直接复用的关键词检索模板。

---

## 一、日志级别关键词与优先级

| 关键词 | 常见语义 | 处置优先级 | 典型动作 |
|---|---|---|---|
| `PANIC` | 不可恢复异常、可能触发进程退出 | P0 | 立即抓 core / 保存现场日志 / 回滚 |
| `ERROR` | 功能失败、请求失败、模块异常 | P0-P1 | 定位调用栈与首个错误点 |
| `failed` / `失败` / `错误` | 英文/中文失败信号词 | P0-P1 | 结合上下文反查函数入口 |
| `WARN` | 非致命异常、降级、重试 | P1-P2 | 观察是否持续放大为 ERROR |
| `INFO` | 生命周期、状态切换、初始化路径 | P2 | 建时间线、核对流程顺序 |
| `DEBUG` | 细粒度调试数据 | P2 | 对比参数与分支条件 |
| `TRACE` | 高频追踪日志 | P2 | 仅在短窗口开启，避免刷盘 |

> 经验规则：故障定位时优先找“第一条 ERROR/PANIC”，而不是最后一条报错。

---

## 二、生命周期关键词（启动/运行/关闭）

### 1) 启动阶段（高频词）
- `初始化`
- `加载`
- `连接`
- `zNetService::init`

重点确认：
1. 初始化顺序是否正确（配置→网络→任务池→业务模块）；
2. 是否出现“加载成功但依赖未就绪”；
3. DB/网络外部依赖是否可达。

### 2) 运行阶段（高频词）
- `validate`
- `zSubNetService::validate`
- `套接口读操作错误`

重点确认：
1. `validate` 是否持续失败并触发连接剔除；
2. 读错误是否集中在某个子网/端口；
3. 是否伴随超时、重连、包长异常。

### 3) 关闭阶段（高频词）
- `final`
- `zTCPTaskPool::final`
- `关闭套接口连接`
- `断开`

重点确认：
1. 是“主动优雅关闭”还是“异常后被动断开”；
2. `final` 是否执行完整（线程池/连接池/句柄释放）；
3. 是否存在重复关闭引发二次错误。

## 三、关键函数导向排查链路

## `zNetService::init`
**定位目标**：服务网络层是否成功初始化。  
**常见失败信号**：端口绑定失败、监听失败、配置缺失。  
**建议联查关键词**：`init failed`、`bind`、`listen`、`端口`、`配置`。

## `zSubNetService::validate`
**定位目标**：子网络会话在运行期的健康检查。  
**常见失败信号**：心跳超时、连接不可用、读写异常。  
**建议联查关键词**：`validate failed`、`timeout`、`断开`、`重连`。

## `zTCPTaskPool::final`
**定位目标**：TCP 任务池是否完成清理与退出。  
**常见失败信号**：线程未退出、任务堆积、句柄泄露。  
**建议联查关键词**：`final`、`join`、`task queue`、`关闭套接口连接`。

## 四、故障分类与快速判定

| 现象 | 首检关键词 | 大概率方向 | 下一步 |
|---|---|---|---|
| 启动即退出 | `PANIC` / `ERROR` / `init failed` | 配置错误、端口冲突、关键依赖缺失 | 核对配置与端口占用 |
| 登录/跨服偶发失败 | `validate` / `断开` / `套接口读操作错误` | 网络抖动、子连接不稳定 | 拉取连接生命周期日志 |
| 高峰期大量超时 | `WARN`→`ERROR` 演化 | 线程池/连接池瓶颈 | 观察任务堆积与池参数 |
| 停服后进程残留 | `final` / `zTCPTaskPool::final` | 清理链路不完整 | 核查线程与 socket 回收 |

## 五、推荐检索语句（可直接用于 rg / 日志平台）

### 1) 等级优先检索
- `PANIC|ERROR|failed|失败|错误`
- `WARN|timeout|断开`
- `INFO|初始化|加载|连接|final`

### 2) 网络生命周期检索
- `zNetService::init|zSubNetService::validate|zTCPTaskPool::final`
- `关闭套接口连接|套接口读操作错误|断开|连接`

### 3) 联合检索（定位首个异常）
- `ERROR.*init|init.*ERROR`
- `validate.*failed|failed.*validate`
- `final.*ERROR|ERROR.*final`

---

## 六、二开时的日志规范建议

1. **初始化日志必须带配置上下文**（端口、服务名、配置版本）。
2. **validate 失败日志必须带连接标识**（fd、对端 IP、子网 ID）。
3. **final 日志必须分阶段**（停止接收→排空任务→关闭连接→资源回收）。
4. 错误日志统一包含：`模块 + 函数 + 错误码 + 关键参数`。
5. 中英文关键字尽量并存（如 `failed/失败`），便于统一检索。

---

## 七、排查流程模板（值班版）

1. 按时间窗口提取 `PANIC/ERROR`，锁定第一条异常；
2. 回溯 30~120 秒内 `INFO/DEBUG` 建立调用时序；
3. 聚焦 `zNetService::init` / `zSubNetService::validate` / `zTCPTaskPool::final` 相关日志；
4. 判断阶段：启动问题、运行问题、关闭问题；
5. 形成结论：配置问题 / 网络问题 / 线程池问题 / 外部依赖问题；
6. 输出修复动作与复现条件，并补充监控告警关键词。

该模板可直接作为线上故障复盘标准流程。
