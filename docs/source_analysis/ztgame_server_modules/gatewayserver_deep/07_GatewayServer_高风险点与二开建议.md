# GatewayServer 高风险点与二开建议

## 登录入口风险
- `verifyConn + waitSync` 为串联关键路径，任何异步状态遗漏会造成“幽灵连接”或卡死。

## 连接池风险
- taskPool 容量/回收参数硬编码较多（4096/65000/5000），在高峰期易出现误判与抖动。

## Session 协作风险
- Session 断链即触发网关终止，故障域过大。

## 协议错位风险
- `CMD_GATE`/`CMD_FORWARD` 结构体长度和 `para` 强耦合，客户端/Session 任一端升级不同步会直接错包。

## 防刷误杀风险
- 包频限制 + 角色流程校验较严格，网络抖动场景可能误杀。

## 推荐安全改造点
1. 登录状态机加可观测埋点（每状态计数和耗时）。
2. `LoginSessionManager` 改为单锁原子更新，修复潜在迭代器风险。
3. 初始握手加随机挑战，替代固定 RC5 key。
4. `CMD_GATE` 分发拆表，减少超大 switch 风险。

## 暂不建议改造点
- 不建议直接变更 `SessionCommand/BillCommand` 协议结构（跨服务冲击大）。
- 不建议一次性替换线程池模型（涉及 base 公共层）。
