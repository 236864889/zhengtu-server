# 高风险点与二开建议
## 高风险点
1. 无显式事务，建角/删角/多步查询一致性不足。  
2. 下线写回依赖 Scene 触发，Record 无 durable queue，崩溃有丢档窗口。  
3. 异步回包乱序可能导致 Scene 状态机误判。  
4. `charbase_define` 超长且耦合，字段改动极易破坏兼容。  
5. SQL 拼接+escape 混用，审计难度高。  
6. `RecordEditor` 工具代码存在明显越界/裸指针风险（不应上线运行）。

## 推荐改造
- S1：写回请求引入持久队列或幂等日志。  
- S1：建角/删角流程加事务与唯一约束错误码映射。  
- S2：字段映射自动化校验（结构体/列名哈希）。  
- S2：慢 SQL 观测与按 accid/charid 索引审计。

## 暂不建议改造
- 不建议直接重排 `RecordCommand/CharBase` 公共结构。  
- 不建议先改协议再补工具链，应先做可观测性和一致性护栏。
