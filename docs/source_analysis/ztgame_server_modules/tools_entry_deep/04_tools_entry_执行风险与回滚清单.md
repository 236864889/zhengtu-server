# tools 执行风险与回滚清单（静态）

## 风险矩阵

| 工具 | 写文件风险 | 写库风险 | 删除/覆盖风险 | 资源生成风险 | 长时运行/阻塞风险 | 结论 |
|---|---|---|---|---|---|---|
| zntop | 有（`outfile` 追加写） | 无直接 | 低（追加模式） | 有（监控快照） | 高（循环刷新、终端占用） | 中风险 |

| datetime | 无显著 | 无 | 低 | 无 | 低 | 低风险 |

## 典型高风险场景
1. 使用默认参数直接运行 `zebraclientService/skill_test_client`，误连历史内网 IP。
2. 启用建号/改密/角色相关参数，触发服务端真实业务写入。
3. `loop_run/random_role/login_sleep` 配置导致长时间压测行为，影响目标环境稳定性。

## 回滚清单（执行前必须具备）
1. **网络隔离**：仅允许指向沙箱服务地址（127.0.0.1/专用测试网段）。
2. **账号隔离**：使用一次性测试账号段，禁止复用生产账号。
3. **写库隔离**：服务端必须连接独立测试库，且预先快照备份。
4. **输出隔离**：`zntop --outfile` 指向临时目录（如 `/tmp/zt_tools/`）。
5. **回滚策略**：
   - 账号侧：批量删除本轮创建账号/角色（需服务端脚本支持）；
   - 文件侧：清理监控输出与日志临时文件；
   - 观测侧：记录开始/结束时间、参数、影响范围。

## 不建议直接运行列表
- `zebraclientService`、`skill_test_client`：在未完成 dry-run 改造前，不建议任何环境直接执行。
- `zntop`：未限定 `outfile`/运行时长前，不建议后台长期执行。
