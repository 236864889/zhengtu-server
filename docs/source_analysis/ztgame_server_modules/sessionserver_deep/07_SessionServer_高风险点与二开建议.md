# SessionServer 高风险点与二开建议

## 高风险点
1. 协议分发巨石函数（`SessionTask.cpp`）改动易引入隐性回归。
2. Record 断链触发停服，外部依赖过强。
3. 多业务模块直接耦合 DBConnPool + 在线会话，事务边界弱。
4. 广播/国家路由逻辑分散，可能出现跨服不一致。
5. 线程池 + 会话容器并发访问，锁粒度与一致性需谨慎。

## 推荐改造
- 先做“只读可观测性”：命令计数、错误码、慢 SQL、广播路径日志。
- 将 `cmd/para` 分发表外置（至少先文档化矩阵）。
- 对 Record 连接增加降级策略（只冻结部分功能而非全服退出）。

## 暂不建议
- 直接重构 SessionTask 全量分支。
- 在未补齐集成回归脚本前调整会话对象字段布局。
