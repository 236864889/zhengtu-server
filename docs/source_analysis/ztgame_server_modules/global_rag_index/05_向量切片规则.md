# 向量切片规则

## Markdown 文档切片规则
- 按一级/二级标题切片；每片保留标题路径。
- 单片建议 500~1200 中文字，超长段落按编号列表再拆分。

## JSONL manifest 入库规则
- 每行一个 JSON，不跨行；保留原字段并增加增强字段。
- 入库键：`path + module + level` 作为去重主键候选。

## 源码入库规则
- 按函数/类/配置段切片，保留上下游调用注释。
- 优先导入 manifest 的 S/A 级 `path`。

## 专项切片
- 按函数链切片：登录链、入场链、保存链、充值链。
- 按配置字段切片：ServerList、端口、DB连接、开关值。
- 按协议命令切片：cmd→handler→downstream。
- 按 XML 事件切片：quest/source 事件名→脚本函数映射。
- 按风险点切片：高风险默认值、一致性边界、误用工具。

## chunk 长度建议
- 文档类：500~1200字；源码类：80~220行；配置类：30~120行。

## metadata 字段建议
- `project=ztgame_server`
- `module=`
- `domain=`
- `source_path=`
- `deep_doc=`
- `rag_level=`
- `chain=`
- `risk=`
- `function=`
- `config_key=`
- `protocol=`
- `service=`
