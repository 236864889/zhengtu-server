# 高风险点与二开建议
## 高风险
1. 资金链路跨“本地DB + 外部计费”双写，缺统一事务。
2. 重复扣费防护依赖内存 `tid`，进程重启窗口存在风险。
3. SQL 高频更新集中在 `BALANCE`，热点账号行锁争用可能明显。
4. 补单表 `RESTORE*` 若堆积，会导致登录补发时间膨胀。

## 推荐改造
- 引入持久化幂等表（tid唯一索引）。
- 关键扣费流程改为“先记账事件表，再异步结算+状态机”。
- 为 `BALANCE(accid)`、`CONSIGN*(accid,price,time)`、`RESTORE*(accid)` 建索引核查清单。
- 增加对账任务：外部计费流水 vs Bill 本地流水。

## 暂不建议
- 直接改协议号/命令结构（跨服务影响巨大）。
- 一次性重写钱庄系统（历史逻辑复杂、回归成本高）。
