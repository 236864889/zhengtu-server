# base 配置与 DB 初始化时序图（文字版）

## 场景 1：进程启动读取配置
1. `main()` 解析启动参数。
2. 通过 `zConfile::parse(...)` 读取服务配置段。
3. 将端口/IP/线程等参数写入服务对象。
4. 记录配置加载结果日志。

## 场景 2：XML 配置加载
1. 业务初始化函数调用 `zXMLParser`。
2. 读取 `GameConfig.xml`、场景配置、商城/NPC 配置等。
3. 失败时记录错误并中断初始化（部分模块会 `return false`）。
4. 成功后缓存到管理器/全局结构。

## 场景 3：数据库初始化
1. 构造 `zDatabaseManager` / `zMysqlDBConnPool`。
2. 按配置创建连接池（host/port/user/password/dbname）。
3. 执行连通性检测（首次 query/ping）。
4. 对外暴露 `dbConnPool` 给业务管理器调用。

## 场景 4：业务首次查询
1. 业务模块（如 Session 子系统）发起 `exeSelectLimit`/`query`。
2. 连接池分配连接并执行 SQL。
3. 返回结果集并反序列化到业务对象。
4. 失败时记录日志并按业务策略重试/返回错误。

## 场景 5：停服释放
1. 停止接收新请求。
2. 等待未完成 DB 请求收敛。
3. 释放连接池与 DB 管理器。
4. 输出 `final` 完成日志。

## 风险点
- 配置键缺失：导致端口错误或 DB 连接失败。
- XML 字段类型变化：触发初始化解析失败。
- 连接池参数不合理：高峰期请求堆积。
- 停服阶段强杀：可能造成未提交事务/脏状态。

## 建议监控指标
- 配置加载成功率与耗时。
- DB 建连成功率、重连次数、平均查询耗时。
- 连接池活跃连接数、等待队列长度。
- 初始化阶段 fatal/error 日志计数。
