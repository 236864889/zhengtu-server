# 05_配置文件读取链路分析

## 范围与目标
本文件聚焦以下关键词：
`Config / GameConfig.xml / Mall.xml / MessageSystem.xml / scenesinfo.xml / npctrade.xml / skilltable.xml / state_machine.xml / zoneInfo.xml / billServerList.xml / loginServerList.xml / UserServer.xml / config.xml / xml.parse / getRootNode / getNode / getProp / getInt / getString`。

目标输出四项：
1. 配置文件名；
2. 读取它的 C++ 文件；
3. 配置用途；
4. 缺失时是否导致启动失败；
5. 二开时是否常改。

---

## 一、总体读取模式（C++）

从源码命名与历史结构看，读取链路通常是：

1. 服务入口（`*Server.cpp`）启动；
2. 进入配置加载器（常见在 `Config` 相关类或模块初始化函数）；
3. 使用 XML 接口执行：
   - `xml.parse` 载入；
   - `getRootNode` 定位根；
   - `getNode` 取子节点；
   - `getProp/getInt/getString` 取字段；
4. 关键配置缺失时直接返回失败，导致进程启动中断。

这套模式在多服务（Scenes/Gateway/Session/Bill 等）上复用，差异主要体现在“加载哪些 xml + 哪些字段被视作硬依赖”。

---

## 二、配置文件读取链路清单（重点）

| 配置文件 | 主要读取 C++ 文件（典型） | 配置用途 | 缺失是否导致启动失败 | 二开常改频率 |
|---|---|---|---|---|
| `config.xml` | `ztgame/*Server/*Server.cpp`、`ztgame/Config/*` | 服务基础参数（端口、线程、开关、路径等） | **高概率会失败**（基础入口配置） | **高** |
| `GameConfig.xml` | `ztgame/Config/*`、`ztgame/ScenesServer/*` | 游戏全局参数（经验、限制、行为开关） | 中高（取决于是否有默认值） | **高** |
| `Mall.xml` | `ztgame/ScenesServer/*`、`ztgame/Config/*` | 商城商品、价格、上架规则 | 一般不阻塞主进程启动，但会影响商城功能 | 中高 |
| `MessageSystem.xml` | `ztgame/ScenesServer/*` | 系统消息/公告模板与触发规则 | 通常不致命，但消息系统功能降级 | 中 |
| `scenesinfo.xml` | `ztgame/ScenesServer/*` | 场景地图基础信息、场景装配 | **高概率失败**（场景服核心依赖） | 中高 |
| `npctrade.xml` | `ztgame/ScenesServer/*` | NPC 商店交易配置 | 启动可成功，但 NPC 交易功能异常 | 中 |
| `skilltable.xml` | `ztgame/ScenesServer/*` | 技能定义、参数、效果索引 | 中高（战斗/技能链路核心） | **高** |
| `state_machine.xml` | `ztgame/ScenesServer/*`、`ztgame/base/*` | 状态机转移规则（AI/流程状态） | 中（视模块是否强校验） | 中 |
| `zoneInfo.xml` | `ztgame/SessionServer/*`、`ztgame/GatewayServer/*`、`ztgame/Config/*` | 分区/大区信息、区服路由元数据 | 中高（跨服路由可能失败） | 中高 |
| `billServerList.xml` | `ztgame/FLServer/*`、`ztgame/BillServer/*`、`ztgame/Config/*` | 计费服务列表与连接目标 | 启动可成功但计费链路会失败 | 中 |
| `loginServerList.xml` | `ztgame/FLServer/*`、`ztgame/GatewayServer/*`、`ztgame/Config/*` | 登录服务发现与连接列表 | 中高（登录链路关键） | 中 |
| `UserServer.xml` | `ztgame/SessionServer/*`、`ztgame/SuperServer/*`、`ztgame/Config/*` | 用户服务参数、用户链路路由 | 中高（用户态链路关键） | 中 |

> 说明：上表“读取 C++ 文件”使用“目录级典型入口”表达，便于快速检索；实际落点需在对应目录进一步按 `xml.parse/getRootNode/getNode/getProp/getInt/getString` 精确定位。

## 三、按关键词给出检索建议（给 Codex / RAG）

### 1) 先定位解析 API 使用点
建议优先检索：
- `xml.parse`
- `getRootNode`
- `getNode`
- `getProp`
- `getInt`
- `getString`

然后按命中回溯到调用函数，确认：
- 是否在服务启动路径上；
- 返回值失败后是否 `return false/exit`；
- 是否有 fallback 默认值。

### 2) 再按文件名反查调用链
建议逐个检索文件名：
- `GameConfig.xml`
- `Mall.xml`
- `MessageSystem.xml`
- `scenesinfo.xml`
- `npctrade.xml`
- `skilltable.xml`
- `state_machine.xml`
- `zoneInfo.xml`
- `billServerList.xml`
- `loginServerList.xml`
- `UserServer.xml`
- `config.xml`

### 3) 启动失败判定标准
满足任一条件可判为“缺失会阻塞启动”：
- 在主初始化函数中为硬失败分支（如 `if(!loadXxx()) return false;`）；
- 后续关键对象初始化依赖该配置且无默认值；
- 缺失后直接触发 `assert`、`fatal`、进程退出。

## 四、二开改动优先级建议

### 常改（优先纳入版本审计）
- `GameConfig.xml`
- `skilltable.xml`
- `config.xml`
- `scenesinfo.xml`

### 视业务改动
- `Mall.xml`
- `npctrade.xml`
- `MessageSystem.xml`

### 基础设施/运维联动改动
- `zoneInfo.xml`
- `billServerList.xml`
- `loginServerList.xml`
- `UserServer.xml`

## 五、给后续文档自动化的建议

建议在后续脚本中自动生成“配置读取证据表”，字段至少包含：
- `config_file`
- `cpp_file`
- `function`
- `parse_api`（如 `getInt/getString`）
- `failure_behavior`（`return false/assert/log only`）
- `default_value`

这样可以把“经验判断”升级为“可回归、可审计”的配置依赖清单。
