# 06_数据库访问链路分析

## 范围与关键词
本分析聚焦以下数据库与 SQL 关键词：
`mysql / mysql_config / zDatabase / zDatabaseManager / zMysqlDBConnPool / query / exec / select / insert / update / delete / FLServerDB.sql / ZtGameDB.sql / ACCSTORE / POINTBONUS / USER / ROLE / CHAR / ACCOUNT`。

输出目标：
1. 数据库访问主链（初始化→连接池→执行 SQL）；
2. 关键类与函数定位；
3. 典型 SQL 操作与高风险改动点；
4. 与 `FLServerDB.sql`、`ZtGameDB.sql` 的映射关注点。

---

## 一、数据库访问总体链路

典型运行链路可抽象为：

1. 服务启动读取 `mysql_config`（或等价数据库配置）；
2. 通过 `zDatabaseManager` 管理数据库实例；
3. 底层使用 `zMysqlDBConnPool` 维护连接池；
4. 业务层经 `zDatabase`（及其封装）发起 `query/exec`；
5. SQL 层落到 `select/insert/update/delete`；
6. 结果回写业务对象（账号、角色、道具、计费点数等）。

该模式通常跨多个服务复用（登录、会话、场景、计费），区别在于：
- 连接目标库不同；
- SQL 表结构不同；
- 失败重试与容错策略不同。

## 二、关键词→职责映射（核心）

| 关键词 | 角色定位 | 典型职责 | 关注风险 |
|---|---|---|---|
| `zDatabase` | DB 访问抽象层 | 执行 SQL、结果集封装、错误回传 | 错误码吞没、事务边界不清 |
| `zDatabaseManager` | DB 实例管理层 | 初始化数据库连接对象、分库路由 | 多库配置错配导致“连得上但查错库” |
| `zMysqlDBConnPool` | 连接池层 | 建连、复用、回收、并发控制 | 连接泄露、峰值阻塞、重连风暴 |
| `mysql_config` | 配置入口 | host/port/user/pass/dbname/pool size | 配置漂移、明文凭据、环境混用 |
| `query` | 读操作入口 | `select` 主流程，返回结果集 | 大查询拖垮主线程、未分页 |
| `exec` | 写操作入口 | `insert/update/delete` 与 DDL/DML | 幂等性不足、失败重放脏写 |

## 三、SQL 操作链路（按语义）

### 1) `select`
- 用途：账号校验、角色载入、商城/状态查询、日志追踪。
- 关注：
  - 是否走索引字段；
  - 是否存在全表扫描；
  - 是否在高频路径执行同步阻塞查询。

### 2) `insert`
- 用途：新账号/新角色创建、流水记录、奖励入账。
- 关注：
  - 主键冲突处理；
  - 重复请求幂等；
  - 插入后回填 ID 的一致性。

### 3) `update`
- 用途：角色属性变更、点券变更、任务状态持久化。
- 关注：
  - 并发覆盖（最后写入覆盖）；
  - 条件更新是否包含版本/时间戳；
  - 跨表更新是否需要事务。

### 4) `delete`
- 用途：角色删除、过期数据清理、回滚脏数据。
- 关注：
  - 误删不可恢复；
  - 级联关系是否完整；
  - 是否具备审计日志。

## 四、与 SQL 文件的映射关注点

| SQL 文件 | 角色 | 建议核查点 | 二开常改程度 |
|---|---|---|---|
| `FLServerDB.sql` | 登录/平台/计费相关库结构（通常） | 账号表、点数表、渠道/计费流水字段 | 中高 |
| `ZtGameDB.sql` | 游戏主库结构（角色/道具/任务等） | 角色主表、物品表、任务/状态字段、索引设计 | **高** |

> 说明：上述“角色”是按项目命名惯例给出的工程判断。实际落地需结合建表语句与服务 SQL 调用点逐条对照。

## 五、重点业务实体关键词（表/域）

以下关键词常用于账号与角色主链，建议优先建立“字段字典 + 调用反向索引”：

- `ACCOUNT`
  - 常见语义：账号主标识、登录态绑定、平台关联。
- `USER`
  - 常见语义：用户元信息（可能与 ACCOUNT 分层）。
- `ROLE` / `CHAR`
  - 常见语义：角色核心数据（等级、职业、货币、位置、状态）。
- `ACCSTORE`
  - 常见语义：账号仓库/跨角色共享存储。
- `POINTBONUS`
  - 常见语义：点券/积分/奖励累计与发放记录。

### 这些实体改动的高风险点
1. 字段类型变化（`int`→`bigint`、`varchar` 长度变化）导致 C++ 读写截断；
2. 非空约束变化导致旧逻辑 `insert` 失败；
3. 索引调整导致线上查询计划突变；
4. 角色与账号关联键变化引发“串号/读错角色”。

## 七、缺失/故障对启动与运行的影响（经验判定）

| 依赖项 | 启动影响 | 运行期影响 |
|---|---|---|
| `mysql_config` 缺失/错误 | 常见为启动失败或 DB 模块初始化失败 | 无法读写核心数据 |
| 连接池参数异常（过小/错误） | 可能可启动 | 高峰期阻塞、超时、雪崩重连 |
| 关键表缺失（如账号/角色主表） | 可能在首个请求时报错 | 登录失败、建角失败、存档失败 |
| 字段不兼容（脚本与代码版本不一致） | 启动可能通过 | 运行中出现写失败或脏数据 |

## 八、二开改动建议（优先级）

### P0（上线前必须回归）
- 涉及 `ACCOUNT/USER/ROLE/CHAR` 主链字段与索引；
- 涉及 `POINTBONUS` 计费/积分结算逻辑；
- 任何 `update/delete` 条件改动。

### P1（强建议回归）
- `ACCSTORE` 仓储/共享资产结构调整；
- 连接池参数、重连与超时配置调整；
- 跨服务共享 SQL 片段改动。

### P2（常规变更）
- 仅新增非关键字段且具备默认值；
- 离线统计类查询优化（不在主链路）。
