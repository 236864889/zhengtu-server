# P1-04 客户端登录器联动方案

## 1. 方案目标

本方案用于指导外部 C# 登录器在**不改客户端源码、不改协议**前提下，正确联动并启动 ztgame.dat 客户端，确保“区服配置 -> 客户端登录UI -> 登录服认证 -> 二跳游戏服 -> 选角进场景”链路稳定可用。

---

## 2. 已有结论引用

基于前序结论，本方案采用如下前提：

- **P0-01**：`config.ini` 中 `Server/servername/loginAddress/loginPort/zone` 是登录器应重点写入字段；`other/version` 在版本联动/AUTOPLAY链路下有意义；`video/*`、`audio/*` 不建议覆盖。  
- **P0-02**：客户端启动后会先做资源与 GUI 初始化，再出现登录界面；登录服连接/登录动作不在初始化第一步直接完成。  
- **P0-03**：RC5/DES 切换由客户端内部网络层根据流程状态控制，登录成功后二跳地址来自 `stServerReturnLoginSuccessCmd` 的 `pstrIP/wdPort`。  
- **P1-03**：登录界面、选角界面、UI 事件与协议发送由客户端 GUI 系统负责，外部登录器不应越权替代。

---

## 3. 登录器职责边界

| 模块 | 职责 | 是否由登录器处理 |
|---|---|---|
| C# 登录器 | 客户端目录检查、关键资源检查、写 `config.ini`、启动进程、错误提示 | 是 |
| ztgame.dat 客户端 | 显示登录UI、发登录协议、RC5/DES切换、处理登录成功包、二跳连接、选角 | 否 |
| 服务端 | 账号校验、版本校验、下发二跳IP/端口/会话key、选角与进场景校验 | 否 |

边界原则：登录器只做“准备与拉起”，不做“协议与会话控制”。

---

## 4. 推荐启动流程

推荐流程（文字图）：

登录器启动  
-> 检查客户端目录  
-> 检查关键资源文件  
-> 写入 `config.ini`（区服字段）  
-> （可选）写账号记忆字段  
-> （可选）传命令行参数（仅特定场景）  
-> 启动 `ztgame.dat` / `ztgame.exe`  
-> 客户端显示登录界面  
-> 客户端自行完成连接、RC5/DES切换、二跳与选角进场景。

---

## 5. config.ini 写入策略

### 5.1 推荐写入字段

| section | 字段 | 示例值 | 是否必须 | 说明 |
|---|---|---|---|---|
| Server | servername | 测试一区 | 是 | 窗口标题与区服显示 |
| Server | loginAddress | 127.0.0.1 | 是 | 登录服地址 |
| Server | loginPort | 7000 | 是 | 登录服端口 |
| Server | zone | 1 | 是 | 区号 |
| Server | autoreconnect | 1 | 建议 | 控制自动重连策略 |
| other | version | 1999 / 业务版本号 | 建议 | 版本联动（AUTOPLAY/版本校验路径） |

### 5.2 不建议覆盖字段

- `video/*`
- `audio/*`
- `other/single`
- `other/autogame`
- `other/InitMap`
- `other/InitX`
- `other/InitY`

原因：这些属于玩家本地偏好或调试项，登录器覆盖会增加黑屏、体验回退、调试态异常风险。

## 6. 命令行参数策略

### 6.1 覆盖逻辑

源码存在 `__argc == 5` 的覆盖分支：

- `__targv[2]` -> `loginAddress`
- `__targv[3]` -> `loginPort`
- `__targv[4]` -> `zone`

### 6.2 使用建议

- **常规推荐**：只写 `config.ini`，不传参数（稳定、易排查）。
- **灰度/临时切服**：可用命令行覆盖，避免改动本地配置文件。
- **优先级**：命令行（`__argc==5`） > `config.ini` 读取值。

### 6.3 注意

源码还存在 `__argc != 5 && __argc != 2` 的参数约束判断，登录器应避免传入无关参数个数，防止触发异常分支。

---

## 7. 启动目标判断：ztgame.dat / ztgame.exe

### 7.1 判断原则

老项目可能将主程序命名为 `.dat`，因此不能仅凭后缀判断可执行性。

### 7.2 推荐优先级

1. 如果 `ztgame.dat` 存在且是 PE（`MZ` + `PE\0\0`），优先启动 `ztgame.dat`；
2. 否则若 `ztgame.exe` 存在且是 PE，启动 `ztgame.exe`；
3. 否则提示“客户端主程序缺失或损坏”。

### 7.3 说明

本阶段不运行未知 exe，仅给出静态联动策略。

---

## 8. 登录器不需要处理的事项

以下内容全部由客户端内部完成，登录器不应接管：

- 不需要处理 RC5；
- 不需要处理 DES；
- 不需要解析 `stServerReturnLoginSuccessCmd`；
- 不需要自己做二跳连接游戏服；
- 不需要发送 `stUserVerifyVerCmd`；
- 不需要发送 `stPasswdLogonUserCmd`；
- 不需要发送 `stLoginSelectUserCmd`。

结论：登录器不应绕过 `GuiLogin` 与客户端网络状态机直接发包。

## 9. 启动前资源完整性检查

| 文件 | 是否必须 | 缺失提示 | 来源结论 |
|---|---|---|---|
| `config.ini` | 是 | 配置文件缺失，无法确定区服参数 | P0-01 |
| `ztgame.dat` / `ztgame.exe` | 是 | 客户端主程序缺失或不可执行 | P0-02 |
| `data/datas.pak` | 是 | 核心数据缺失，客户端初始化可能失败 | P0-02 / P1-01 |
| `data/interfaces.gl` | 是 | UI 主图集缺失 | P0-02 / P1-03 |
| `data/login.gl` | 是 | 登录界面图集缺失 | P0-02 / P1-03 |
| `data/logo.gl` | 建议 | 登录动画资源缺失 | P1-03 |
| `data/icons.gl` | 是 | 图标图集缺失，技能/NPC图标异常 | P1-03 |
| `data/items.gl` | 是 | 物品UI图标异常 | P1-01 / P1-03 |
| `data/sound.pak` | 建议 | 声音资源缺失（可降级） | P0-02 / P1-01 |
| `data/Minimap.gl` | 建议 | 小地图资源缺失 | P1-03 |

## 10. 错误分类与提示策略

| 错误类型 | 可能原因 | 登录器能否判断 | 建议提示 |
|---|---|---|---|
| 主程序缺失 | `ztgame.dat/ztgame.exe` 不存在或非PE | 能 | 客户端主程序缺失/损坏，请修复安装 |
| config.ini 写入失败 | 无权限、文件锁定 | 能 | 无法写入配置，请管理员权限重试 |
| 资源缺失 | `datas.pak`/`interfaces.gl` 等缺失 | 能 | 客户端资源不完整，请执行修复 |
| 无法启动进程 | 路径错误、权限问题 | 能 | 客户端启动失败，请检查权限与杀软 |
| 登录服连接失败 | IP/端口错误或网络不可达 | 部分 | 无法连接登录服务器，请检查区服配置/网络 |
| 版本失败 | `stUserVerifyVerCmd.version` 不匹配 | 否（仅间接） | 版本不匹配，请更新客户端 |
| 账号密码失败 | 账号错误、封禁、口令错误 | 否（仅间接） | 账号或密码错误（以客户端提示为准） |
| 二跳失败 | `pstrIP/wdPort` 不可达、网关故障 | 否（仅间接） | 登录成功后连接游戏服失败 |
| 选角失败 | 角色索引/状态异常 | 否（仅间接） | 选角失败，请重试或更换角色 |
| 资源显示异常 | 图集/文本资源缺失或错版 | 部分 | 资源异常，请执行完整校验 |

## 11. 与客户端 UI 的关系

- 登录器可以做“区服选择 + 配置写入 + 启动”；
- 建议保留客户端原 `GuiLogin` 登录流程；
- 可在登录器中做公告/区服列表，但不建议替代客户端协议发送；
- 若需要账号记忆，建议写登录器自身本地安全存储，不直接篡改客户端协议链；
- 不建议绕过客户端 UI 直接发 `stUserRequestLoginCmd/stLoginSelectUserCmd`。

---

## 12. C# 登录器实现建议

建议功能模块：

1. JSON 区服配置（区名、IP、端口、zone、状态）；
2. MD5/SHA256 自更新（登录器自身与关键文件）；
3. 资源完整性检查（启动前）；
4. `config.ini` 安全写入（原子写/备份回滚）；
5. 启动参数可选覆盖（灰度场景）；
6. 日志记录（写配置、启动参数、错误码、系统信息）；
7. 错误提示分级（可修复/不可修复）；
8. 自动识别 `ztgame.dat/ztgame.exe` 主程序。

## 15. 结论与下一步

- 本阶段结论：C# 登录器最佳实践是“**写配置 + 资源校验 + 启动**”，登录与加密/二跳/选角全部交给客户端内部流程。
- 若登录器联动方案清晰：下一步进入 **D1-04 C# 登录器联调实测方案**。
- 若主程序识别仍不确定：先做 **D1-04A ztgame.dat / ztgame.exe 主程序识别验证**。
