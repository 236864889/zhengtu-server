# P1-05 客户端二开优先级路线图

## 1. 路线图目标

本文用于指导 ztgame.dat 客户端后续二开、联调、资源整理、登录器改造、Unity/UE5 重构的**执行顺序**，目标是先做低风险高收益，再逐步进入中高风险改动，避免“先改高风险、后补基础”的返工。

---

## 2. 已完成分析基础

已完成文档与作用如下：

- `P0-01 config.ini 字段验证`：确认登录器应写字段与字段优先级。

- `P0-04 客户端服务端表字段漂移验证`：约束表字段双端一致性风险。
- `P0-05 地图阻挡一致性验证`：确认地图阻挡链路与一致性风险点。

## 4. P0 必须先做事项

必须先完成：

- C# 登录器联调；
- 主程序 `ztgame.dat/ztgame.exe` 识别；
- `config.ini` 写入稳定；
- 启动前资源完整性检查；
- 登录服连接验证；
- 二跳连接验证；
- 选角进场景验证。

原因：这些是“所有二开可验证”的前提。若基础启动/登录链路不稳定，后续 UI、技能、资源、地图改动无法可靠回归。

---

## 5. 第一阶段：低风险高收益二开

优先项（建议先做）：

1. 登录器区服列表
   - 改动位置：C# 登录器
   - 服务端：否
   - 风险：低
   - 验收：可稳定切服并写入 `config.ini`

2. 公告页
   - 改动位置：登录器 UI 或客户端登录页文本区域
   - 服务端：否（静态公告）/可选（远程公告）
   - 风险：低
   - 验收：公告展示不影响登录流程

3. 资源完整性检查
   - 改动位置：登录器
   - 服务端：否
   - 风险：低
   - 验收：缺失资源能提前阻断并提示

4. UI 文案
   - 改动位置：UI 文本与描述
   - 服务端：否
   - 风险：低
   - 验收：文案正确、无协议副作用

5. 图标替换
   - 改动位置：icons/items 对应图集资源
   - 服务端：否
   - 风险：低~中
   - 验收：图标显示正确，帧映射不乱

6. 登录界面美化
   - 改动位置：login/logo/interfaces 图集与布局
   - 服务端：否
   - 风险：低~中
   - 验收：登录界面可用，登录按钮逻辑不变

7. 背包/装备视觉优化
   - 改动位置：GuiPackage/GuiEquip 相关布局与素材
   - 服务端：部分
   - 风险：中
   - 验收：显示正确，不影响穿脱/使用协议

8. 技能图标优化
   - 改动位置：`SkillBase.dwIcon` 映射资源
   - 服务端：否（仅图标）
   - 风险：中
   - 验收：图标、冷却遮罩、快捷栏一致

9. 音效替换
   - 改动位置：sound 资源
   - 服务端：否
   - 风险：低~中
   - 验收：播放正常，无明显音频异常

## 6. 第二阶段：中风险功能二开

包括：

- 新装备外观；
- 新 NPC 展示；
- 新技能表现；
- 小地图优化；
- 任务界面优化；
- 活动界面优化；
- 简单协议功能新增。

关键要求：

- 双端同步点：技能ID/目标类型/冷却/物品与装备字段、命令号；
- 资源同步点：图集帧映射、模型/特效资源路径、音效引用；
- 测试重点：回归登录->进场景->操作->切图完整链路，避免“只看表现不看协议”。

---

## 7. 第三阶段：高风险核心二开

高风险项：

- 技能判定改动；
- 背包/装备操作协议改动；
- 商城/交易/充值相关 UI；
- 地图阻挡/传送点改动；
- 协议结构扩展；
- RenderD3D8 / engine 底层改造。

为何高风险：

- 强双端耦合，容易出现“客户端表现正常但服务端拒绝”；
- 兼容性影响大，回归范围覆盖登录、战斗、交易、地图；
- 一旦失败，故障定位成本高。

前置条件：

- 已有稳定联调环境；
- 已完成字段对齐与协议版本管理；
- 已建立灰度测试与回滚机制。

回滚方案：

- 协议层保留旧版本分支；
- 资源层保留上个稳定包；
- 登录器支持“一键回退到稳定客户端目录”。

## 8. Unity / UE5 重构路线

### 8.1 旧客户端中应保留

- 协议结构与命令语义；
- 技能ID体系与关键表字段；
- 地图逻辑坐标与传送规则。

### 8.2 仅作为数据来源

- PAK/GL 原始资源；
- UI 图集帧映射；
- 技能/物品/NPC 表数据。

### 8.3 必须重做

- 渲染层；
- UI 系统；
- 资源运行时加载链（建议转中间格式）；
- 特效系统（VFX Graph/Niagara）。

### 8.4 最小 MVP 顺序

1. 协议兼容层；
2. 登录/选角；
3. 进场景；
4. 地图坐标；
5. 角色移动；
6. 聊天；
7. 背包/装备；
8. 技能表现；
9. 地图/特效升级。

## 13. 不建议现在做的事项

当前阶段不建议直接做：

- 直接改协议结构；
- 直接改 RenderD3D8；
- 大规模改地图阻挡；
- 直接绕过客户端 GuiLogin；
- 不做资源索引就大改 UI；
- 不做双端字段对比就新增技能/装备。

---

## 14. 推荐下一步落地任务

优先建议：

- **首选**：`D1-04A ztgame.dat / ztgame.exe 主程序识别验证`。

分支策略：

- 如果已有 C# 登录器源码：优先进入 **C# 登录器源码级改造方案**；
- 如果尚无源码或源码不可改：先做 **D1-04A**，确保启动识别链路绝对稳定。

---

## 15. 结论

客户端二开推荐顺序：

1. 先登录器与资源校验；
2. 再 UI 与资源轻改；
3. 再技能/装备/NPC 表现扩展；
4. 最后协议、地图、底层渲染与 Unity/UE5 重构。

该顺序能最大化“见效速度 / 风险可控 / 回归可执行性”。
