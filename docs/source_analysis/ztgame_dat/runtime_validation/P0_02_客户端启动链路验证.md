# P0-02 客户端启动链路验证

## 1. 验证目标
静态确认 ztgame.dat 客户端从启动入口到登录界面出现前的实际调用链与关键初始化步骤，定位登录器接入边界与启动失败风险点。

## 2. 搜索范围与方法
- 重点源码：
  - `Client/GameAppation.cpp/.h`
  - `Client/Game.cpp`
  - `Client/GameScene.cpp`
  - `Client/GuiLogin*.cpp`
  - `Client/GuiSelectCharDialog.cpp`
  - `engine/source/Appation.cpp`
  - `engine/include/Appation.h`
- 关键词：`WinMain/main/GameMain/InitInstance/LoadConfig/MsgProc/ShowWindow/UpdateWindow/OpenPackFileForRead/GetSoundManager/g_pGameScene/g_pClient/IsDebuggerPresent/__try/__except/SimpleReportError/AddGuiLogin`。

## 3. 启动入口总览
基于源码实际顺序：

`WinMain -> main -> GameMain -> CGameAppation::InitInstance -> LoadConfig -> CAppation::InitInstance(创建窗口/设备) -> 声音系统初始化 -> 预加载GL资源 -> GUI系统初始化 -> CreateGameSystem -> LoadFaceInfo(datas.pak/face.xml) -> ShowWindow/UpdateWindow -> RefreshFrame/Draw循环 -> Game.cpp中AddGuiLogin触发登录UI`

> 说明：登录服务器连接不是在 `InitInstance` 里立即发起，而是进入登录状态后由登录流程触发。

## 4. WinMain / main 入口分析
- 入口位置：`Client/GameAppation.cpp`。
- `WinMain`：`return main(0,NULL);`，主入口转到 C 运行时 `main`。
- `main`：调用 `GameMain(GetModuleHandle(NULL),NULL,NULL)`。
- 反调试：`main` 内存在 `IsDebuggerPresent()` 分支；同时全局还有 `CHECK_DEBUGGER_INIT` 宏位点。
- 异常捕获：`main` 用 `__try/__except(SimpleReportError(...))` 包裹 `GameMain`。
- 命令行解析：`LoadConfig` 中有 `__argc == 5` 覆盖登录参数逻辑；另有 `__argc != 5 && __argc != 2` 的启动参数约束逻辑位点。
- 对登录器影响：
  - 直接启动可行；
  - 可通过参数覆盖登录地址/端口/区号；
  - 若参数格式不对，可能落回 config.ini 默认值。

## 5. CGameAppation 初始化流程

| 顺序 | 调用/对象 | 源码文件 | 函数 | 作用 | 失败风险 |
|---|---|---|---|---|---|

## 6. 配置读取流程
- `LoadConfig` 在 `CGameAppation::InitInstance` 中、`CAppation::InitInstance` 之前执行。  
- 启动链中先读配置再建窗口/设备，因此配置直接影响分辨率、窗口模式、登录地址等关键参数。  
- 详细字段结论已在 P0-01 文档中给出。

## 7. 核心对象创建流程
- `g_pGameScene`：`CGameAppation::InitInstance` 最前段创建。
- `g_pClient`：同上，与 `g_pGameScene` 同阶段创建。
- 声音系统：`CAppation::InitInstance` 成功后初始化，并绑定 `sound.pak`。
- GUI 系统：在 GL 资源预加载后调用 `GetGameGuiManager()->InitCreate/Init`。
- 网络连接时机：**启动时不直接连接**；连接动作在登录流程状态机中触发（`Game.cpp` 登录状态逻辑、后续登录动作）。

## 8. 资源加载流程

| 资源 | 类型 | 调用位置 | 用途 | 缺失后果 |
|---|---|---|---|---|
| `data\sound.pak` | 声音包 | `GameAppation::InitInstance` | 音效/BGM数据源 | 无声或音频异常 |
| `data\interfaces.gl`（及 interfaces1..7） | UI图集 | `GameAppation::InitInstance` | 主界面控件、面板 | UI缺图/黑块 |
| `data\login.gl` | 登录UI图集 | `GameAppation::InitInstance` | 登录界面资源 | 登录界面异常 |
| `data\items.gl` | 道具图集 | `GameAppation::InitInstance` | 背包/道具显示 | 物品图标异常 |
| `data\icons.gl` | 图标图集 | `GameAppation::InitInstance` | NPC/系统图标 | 图标丢失 |
| `data\datas.pak` | 数据包 | `LoadFaceInfo` | 加载 `datas/face.xml` | 表情/字符资源加载失败 |
| `datas/face.xml` | XML | `LoadFaceInfo` | 表情/字符映射 | 聊天表情等功能异常 |

## 9. 登录界面出现前后边界
- 登录 UI 入口：`Game.cpp` 中 `GetGameGuiManager()->AddGuiLogin()`。
- 登录 UI 依赖：已完成 `LoadConfig`、GUI初始化、`login.gl` 预加载。
- 登录 UI 出现前：`CClient` 已创建。
- 登录 UI 出现前：通常尚未连接登录服（连接动作由登录流程触发，不在 `InitInstance` 直接执行）。
- 点击登录后：才进入账号认证与连接相关流程（并在成功后可能二跳连接游戏服）。

## 10. 启动失败风险点

| 风险 | 表现 | 可能文件 | 验证方法 | 优先级 |
|---|---|---|---|---|
| D3D/设备初始化失败 | 无法显示窗口或黑屏退出 | `engine/source/Appation.cpp` | 记录 `GetDevice()->Create` 返回值 | P0 |
| `config.ini` 错误 | 无法连接登录服/显示异常 | `GameAppation.cpp` | 对比 P0-01 字段与默认值 | P0 |
| `interfaces.gl/login.gl` 缺失 | 登录UI异常或缺图 | `GameAppation.cpp` | 缺失文件实验（只读验证） | P1 |
| `datas.pak` 或 `datas/face.xml` 缺失 | 启动后字符/表情异常 | `GameAppation.cpp::LoadFaceInfo` | 日志检查 `OpenPackFileForRead` 失败 | P1 |
| `sound.pak` 缺失 | 无声音或音频异常 | `GameAppation.cpp` + `Media` | 启动时音频初始化日志 | P2 |
| 反调试/异常捕获路径触发 | 直接退出或异常上报 | `GameAppation.cpp` | 调试器附加与非附加对比 | P1 |

## 11. 对 C# 登录器的影响
- 直接启动 ztgame.dat：可行。
- 参数策略：可选传参（`__argc==5` 路径）或只写 `config.ini`。
- 推荐策略：登录器优先写 `config.ini` 的服务器字段，再按需要附加参数覆盖。
- 强建议：启动前先检查关键资源完整性（`sound.pak`、`interfaces.gl`、`login.gl`、`datas.pak`）。
- 启动失败提示：区分“配置错误 / 资源缺失 / 图形设备失败 / 连接失败”四类。

## 12. 下一步动态验证建议
1. 只改 `config.ini` 启动，确认登录界面与窗口标题。  
2. 用命令行参数启动，验证 `loginAddress/loginPort/zone` 覆盖。  
3. 资源缺失测试（只读环境），确认失败表现与日志。  
4. 抓取窗口标题是否读取 `Server/servername`。  
5. 抓取登录服连接时机（是否在点击登录后）。  
6. 建议加日志点：`LoadConfig` 结束、`CAppation::InitInstance` 成功、`AddGuiLogin` 调用前后、`CClient::Connect` 调用处（后续可在调试分支做，不在本阶段改源码）。
