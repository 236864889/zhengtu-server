# P1-02 技能特效链路验证

## 1. 验证目标

本阶段用于确认 ztgame.dat 客户端中“**技能协议 -> 技能表 -> Magic 特效 -> 音效 -> UI显示**”的完整静态链路，重点回答：

- 技能命令从哪里接收、如何分发；
- 技能 ID 如何映射到 `SkillBase/SkillLevelBase`；
- 技能表现如何进入 `Magic` 模块创建特效；
- 音效如何在 `magic_sound/Media` 层播放；
- 技能图标与冷却如何在 `GuiSkill` 侧显示；
- 哪些字段必须双端一致，哪些属于纯表现可调。

## 3. 技能链路总览

按源码实际主链路可归纳为：

服务端技能命令（`stAttackMagicUserCmd` / `stRTMagicUserCmd`）  
-> 客户端收包进入 `ParseMagicMessage`（`Game.cpp`）  
-> 按 `dwUserTempID/byAttackType/byTarget` 定位施法者/目标对象  
-> 分发到 `CNpc::PushCommand` / `CastMagic`  
-> `GetSkillBase(wdMagicType)` + （必要时）`ServerSkillToClientSkill` 映射  
-> `GetScene()->AddMagic(...)` 或 `CNpc::CastMagic(...)` 触发表现  
-> `Magic_CreateMagic(...)` 创建特效实例（`Magic/stMagic.cpp`）  
-> `magic_sound` + `GetSoundManager()->Play(...)` 播放技能相关声音  
-> `GuiSkillTree` 读取 `SkillBase/RoleSkill` 显示图标、状态、冷却。

## 4. 技能协议入口

### 4.1 关键协议结构

`command.h` 中定义技能相关包结构：

- `stAttackMagicUserCmd`（`MAGIC_USERCMD_PARA=5`）：包含施法者ID、目标ID、技能类型 `wdMagicType`、目标坐标 `xDes/yDes`、攻击类型、动作等；
- `stRTMagicUserCmd`（`RTMAGIC_USERCMD_PARA=6`）：包含目标ID、返回码、来源类型、来源ID、HP变化等；
- `RTMAGIC_POS_USERCMD_PARA` 等用于坐标型结果。

### 4.2 客户端解析入口

`Game.cpp::ParseMagicMessage` 按 `byParameterType` 分支处理 `MAGIC_USERCMD_PARA / RTMAGIC_USERCMD_PARA / RTMAGIC_POS_USERCMD_PARA / NPCDEATH_USERCMD_PARA ...`，先解析对象ID与对象类型，再把命令分发到目标对象的 `PushCommand`/`CastMagic` 流程。

### 4.3 技能核心字段来源

- 技能 ID：`stAttackMagicUserCmd::wdMagicType`；
- 目标对象：`dwDefenceTempID` + `byAttackType`；
- 坐标型技能：`xDes/yDes`；
- 命中/结果：`stRTMagicUserCmd::byRetcode`、`dwHP/sdwHP`。

| 协议结构 | 所在文件 | 关键字段 | 用途 | 是否必须服务端一致 |
|---|---|---|---|---|
| `stAttackMagicUserCmd` | `Client/command.h` | `wdMagicType`, `dwUserTempID`, `dwDefenceTempID`, `xDes/yDes`, `byAttackType`, `byAction` | 发起施法与表现触发 | 是 |
| `stRTMagicUserCmd` | `Client/command.h` | `byRetcode`, `dwUserTempID`, `dwSrcTempID`, `dwHP/sdwHP` | 结果回执、命中反馈 | 是 |
| `ParseMagicMessage` | `Client/Game.cpp` | `byParameterType` 分发 | 技能协议路由入口 | 是 |

## 5. 技能表结构入口

### 5.1 表结构定义

`table.h` 定义：

- `SkillBase_t`：静态基础定义（ID、名称、图标、目标类型、距离、类型、消耗、施法方式等）；
- `SkillLevelBase_t`：按等级展开的技能参数（含 `dwIntervalTime`、消耗、目标、图标等）。

### 5.2 读取入口

`table.cpp` 从 `data\datas.pak` 读取：

- `datas\tables\SkillBase.tbl` -> `g_tableSkillBase`
- `datas\tables\SkillLevelBase.tbl` -> `g_tableSkillLevelBase`

### 5.3 查询入口

- `GetSkillBase(dwID)`：从 `g_tableSkillBase` 按 ID 查；
- `GetSkillLevelBase(dwID,dwLevel)`：从 `g_tableSkillLevelBase` 按 (ID,Level) 查。

| 表结构 | 字段 | 用途 | 是否客户端显示 | 是否服务端判定 |
|---|---|---|---|---|
| `SkillBase_t` | `dwID` | 技能主键 | 是 | 是 |
| `SkillBase_t` | `dwIcon` | 图标帧索引 | 是 | 否（表现） |
| `SkillBase_t` | `dwTarget` | 目标类型约束 | 是 | 是 |
| `SkillBase_t` | `dwType` | 主动/被动/状态等 | 是 | 是 |
| `SkillBase_t` | `dwUseMethod` | 施法方式（选中/手选等） | 是 | 是 |
| `SkillLevelBase_t` | `dwLevel` | 技能等级参数 | 是 | 是 |
| `SkillLevelBase_t` | `dwIntervalTime` | 冷却时间参数 | 是 | 是 |
| `SkillLevelBase_t` | `dwMP/dwHP/dwSP` | 消耗参数 | 是 | 是 |

## 6. Magic 特效模块入口

### 6.1 客户端到 Magic 的桥

`CNpc::CastMagic(stAttackMagicUserCmd*)` 是关键桥接点：

1. 用 `wdMagicType` 查 `SkillBase`；
2. 特殊状态下把服务端技能映射为客户端替代技能（组合/宠物等分支）；
3. `ServerSkillToClientSkill` 得到客户端表现技能索引；
4. 根据目标是否存在走 `CastMagic(target,...)` 或 `CastMagic(pos,...)`。

### 6.2 Magic 实例创建

`Magic/stMagic.cpp` 中通过 `Magic_CreateMagic(strName, table)` 创建 iMagic 实例，随后 `CreateMagic()`、`Fly(...)`、`OnMagicBegin(...)` 执行生命周期启动。

### 6.3 特效资源引用方式（静态推断）

链路体现为“技能ID/表现ID -> Magic 名称/脚本 -> `Magic_CreateMagic`”。具体素材文件名在本阶段未解包，不展开到资源实体文件。

| 特效阶段 | 入口函数 | 资源来源 | 触发条件 | 风险 |
|---|---|---|---|---|
| 释放前摇/起手 | `CNpc::CastMagic` | 技能表 + 动作字段 | 收到 `MAGIC_USERCMD_PARA` | 技能ID映射错导致动作错位 |
| 飞行特效 | `Magic_CreateMagic` + `Fly` | Magic 配置/资源 | 有目标或坐标目标 | 跟踪目标丢失导致特效提前释放 |
| 命中特效 | `CastMagic(target,...)` 分支 | Magic 配置/命中事件 | 命中对象存在 | 目标判定不同步 |
| 持续/状态特效 | `stRTMagicUserCmd` + 状态流程 | 技能等级参数 + 状态系统 | 服务端返回状态结果 | 客户端仅表现，易与服务端时长不一致 |

## 7. 技能动作与场景对象联动

- `ParseMagicMessage` 先定位实体（NPC/角色）再下发命令；
- `CNpc::PushCommand` 在 `MAGIC_USERCMD_PARA` 分支中处理动作合法性、主角特殊分支、并调用 `CastMagic`；
- 攻击者/目标定位依赖 `byAttackType + dwDefenceTempID`；
- 坐标型技能走 `xDes/yDes -> GridCenterToPixelPos`；
- 目标不存在时存在回退路径：仍可能直接 `AddMagic` 在目标坐标处播放表现。

结论：对象联动在 `Game.cpp -> Npc.cpp` 已形成完整闭环，`PushCommand` 是战斗命令进入对象行为层的关键节点。

## 8. 技能音效链路

### 8.1 模块关系

- `Magic/stMagic.cpp` 引入 `magic_sound.h`；
- `Magic/magic_sound.cpp` 通过 `GetSoundManager()->Play/SetSoundParam/Stop` 控制3D或场景音；
- `Media/SoundManager.cpp` 提供全局 `GetSoundManager()`。

### 8.2 技能音效触发特征

`CSceneSound::Play()` 会按当前位置、最小/最大距离、loop参数调用 `GetSoundManager()->Play(...)`，说明技能音效绑定到空间参数（位置/朝向/距离衰减），不只是纯2D UI音。

### 8.3 sound.pak 引用关系

声音文件最终由 SoundManager 资源包读取（上一阶段已确认 `SetFilePack("data\\sound.pak")`），技能层只传“声音名 + 参数”，不直接处理包读取细节。

## 9. 技能 UI / 图标 / 冷却显示

### 9.1 图标显示

`GuiSkillTree.cpp` 构建技能按钮时，使用：

- `GetSkillBase((*it).dwID)` 获取技能基础信息；
- `pBtn->SetBitmap(stResourceLocation("data\\icons.gl",1,(*it).dwIcon),...)` 用 `dwIcon` 映射图标帧。

### 9.2 技能状态与冷却

- `CRoleSkill::SetAttrib` 收到服务端技能属性后更新 `m_dwLevel/m_dwExp`；
- `ReSetSkillData(m_pSkillBase,m_dwLevel)` 将等级参数回填到技能实例；
- 根据 `SkillLevelBase.dwIntervalTime` 与服务端同步经验字段推算冷却起点，调用 `SetUseSkillTime`；
- GUI 刷新由 `m_guiSkill->RefreshState()` 与主角绘制禁用状态函数驱动。

### 9.3 技能描述

技能名/描述来自 `SkillBase_t`（`pstrName/strDesc`）并用于提示文本与技能面板。

## 10. 双端必须一致字段

必须保持与服务端一致（否则会出现“能点不能放/表现命中但判定失败”）：

- 技能 ID；
- 技能等级；
- 目标类型；
- 技能类型；
- 释放距离；
- 消耗（MP/HP/SP/道具）；
- 冷却（`dwIntervalTime`）；
- 作用对象与攻击类型（U2U/U2N/N2U/N2N）；
- 伤害/治疗/Buff 结果字段；
- 协议字段顺序与结构体布局；
- 技能命令号（`MAGIC_USERCMD_PARA/RTMAGIC_USERCMD_PARA` 等）。

---

## 11. 客户端可单独调整字段

可在不改变服务端判定前提下单独调整：

- 图标（`dwIcon` 对应图集帧）；
- 名称/描述文案；
- 纯视觉特效样式（粒子、贴图、轨迹）；
- 音效资源与混音参数；
- 技能面板排序与部分UI布局；
- 非判定型表现时序（例如前后摇视觉补间）。

> 约束：不能让视觉效果误导玩家对服务端真实判定（命中范围、持续时间、冷却完成时机）认知。

## 12. Unity / UE5 重构影响

1. 技能 ID 体系必须保留（协议与服务端判定不变）；
2. 服务端战斗判定逻辑不动，新客户端只重建表现层；
3. 技能特效可迁移到 Unity VFX Graph / UE Niagara；
4. 技能数据可迁移为 DataTable / ScriptableObject；
5. 必须建立统一映射表：

`技能ID -> SkillBase/SkillLevel -> 特效资源 -> 音效 -> UI图标 -> 冷却/描述`

6. 对“服务端技能ID -> 客户端替代表现技能（组合态等）”要保留兼容层。

## 14. 结论与下一步

### 14.1 结论

- 技能协议入口明确在 `Game.cpp::ParseMagicMessage`；
- 技能表入口明确在 `table.cpp` 读取 + `table.h` 查询函数；
- 特效入口明确在 `Npc.cpp::CastMagic` 到 `Magic_CreateMagic`；
- 音效入口明确在 `magic_sound.cpp` 到 `GetSoundManager`；
- UI 入口明确在 `GuiSkillTree.cpp`（`dwIcon` 图标映射、冷却/状态展示）。

### 14.2 下一步

- 若链路清晰可继续：进入 **P1-03 UI 与界面资源联动验证**；
