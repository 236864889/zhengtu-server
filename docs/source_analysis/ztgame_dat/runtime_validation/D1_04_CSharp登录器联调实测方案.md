# D1-04 C# 登录器联调实测方案

## 1. 验证目标

本方案用于将 P1-04 的静态联动策略落地为可执行联调步骤，验证 C# 登录器与 ztgame.dat 客户端在真实测试环境中的联动效果，包括主程序识别、资源检查、配置写入、启动、登录、二跳、选角进场景与异常提示完整性。

---

## 2. 前置条件

联调开始前必须具备：

- 可运行客户端目录；
- C# 登录器程序；
- `config.ini` 原始备份；
- `data/datas.pak`；
- `data/interfaces.gl`；
- `data/login.gl`；
- `data/icons.gl`；
- `data/items.gl`；
- 服务端已启动（登录服 + 游戏服）；
- 测试账号（至少 2 组：正确账号 + 错误账号）；
- 抓包工具；
- 日志目录（launcher 与 client 分开记录）。

---

## 3. 测试环境目录规范

建议目录结构：

```text
客户端目录/
  ztgame.dat 或 ztgame.exe
  config.ini
  data/
  launcher/
  logs/
```

建议约定：

- `launcher/` 放 C# 登录器；
- `logs/launcher/` 记录登录器日志；
- `logs/client/` 记录客户端日志或抓包索引；
- 每轮测试前复制 `config.ini.bak` 恢复基线。

---

## 4. 主程序识别测试

目标：验证登录器对 `ztgame.dat/ztgame.exe` 的识别策略是否符合 P1-04。

### 4.1 测试步骤

1. 检查 `ztgame.dat` 文件头是否为 PE（`MZ` + `PE\0\0`）；
2. 检查 `ztgame.exe` 文件头是否为 PE；
3. 两者同时存在时，验证优先级（预期优先 `ztgame.dat`）；
4. 人为移除主程序后，验证错误提示。

### 4.2 记录表

| 测试项 | 文件状态 | 预期结果 | 实际结果 | 是否通过 |
|---|---|---|---|---|
| DAT为PE | 仅 `ztgame.dat` 存在且可执行 | 启动 `ztgame.dat` |  |  |
| EXE为PE | 仅 `ztgame.exe` 存在且可执行 | 启动 `ztgame.exe` |  |  |
| DAT+EXE | 两者均可执行 | 按优先级选择（建议 DAT） |  |  |
| 主程序缺失 | 两者都不存在/不可执行 | 明确提示“主程序缺失或损坏” |  |  |

## 6. config.ini 写入测试

目标：验证登录器写入区服字段是否正确、可回读、不破坏玩家设置。

### 6.1 验证字段

`[Server]`
- `servername`
- `loginAddress`
- `loginPort`
- `zone`
- `autoreconnect`

`[other]`
- `version`

### 6.2 测试步骤

1. 写入前备份 `config.ini`；
2. 登录器写入目标字段；
3. 立即回读并比对；
4. 校验 `video/*` 与 `audio/*` 未被覆盖；
5. 模拟无写权限场景（只读文件）验证错误提示；
6. 测试后恢复 `config.ini.bak`。

---

## 7. 命令行参数测试

目标：验证“不传参/`__argc==5`/错误参数数量”的行为。

### 7.1 场景

1. 不传参数启动（仅依赖 `config.ini`）；
2. 传 `__argc==5` 格式参数（覆盖 `loginAddress/loginPort/zone`）；
3. 传错误参数数量（触发异常分支保护）；
4. 比较参数优先级是否高于 `config.ini`。

记录表：

| 模式 | 参数 | 预期结果 | 是否通过 |
|---|---|---|---|
| 配置模式 | 无参数 | 使用 `config.ini` 区服字段 |  |
| 覆盖模式 | `__argc==5` | 使用参数覆盖地址端口区号 |  |
| 异常参数 | 数量错误 | 提示参数错误或回退默认策略 |  |
| 优先级验证 | 参数与ini冲突 | 参数优先 |  |

## 8. 启动客户端测试

验证项：

- 登录器能否成功拉起客户端进程；
- 工作目录是否指向客户端根目录；
- 启动后是否出现客户端窗口；
- 是否进入 `GuiLogin`；
- 是否生成启动日志（含 PID、命令行、主程序路径）。

建议最少执行 3 轮，排除偶发启动失败。

## 11. 日志与排错字段

建议登录器日志至少记录：

- 启动时间；
- 客户端目录；
- 主程序路径；
- 主程序类型（DAT/EXE/非PE）；
- 写入的区服字段；
- 是否传参；
- 资源检查结果；
- 启动进程 PID；
- 异常信息（异常类型/堆栈/错误码）；
- 用户可见提示文案。

建议日志格式：一行一事件（JSON Line），便于检索与统计。

---

## 12. 联调通过标准

### 12.1 必须通过项（Blocking）

- 主程序识别正确；
- 关键资源检查正确；
- `config.ini` 核心字段写入与回读一致；
- 可稳定启动客户端并进入 `GuiLogin`；
- 正常账号可完成登录 -> 二跳 -> 选角 -> 进场景；
- 关键异常场景有明确、可理解提示。

### 12.2 可接受缺陷

- 非关键建议资源（如 `sound.pak`）缺失时提示文案不完美；
- 日志字段部分缺失但不影响定位主流程问题。

### 12.3 阻断缺陷

- 主程序误识别导致无法启动；
- 覆盖错误字段破坏玩家 `video/audio` 配置；
- 登录器试图直接发协议替代客户端登录；
- 正常参数下无法完成登录主链。

---

## 13. 对后续登录器开发的建议

- 使用 JSON 管理区服；
- 增加 MD5/SHA256 资源校验；
- 支持自动更新与断点续传；
- 提供资源修复入口；
- 增加日志面板与一键导出；
- 统一错误码分类（配置/资源/网络/认证/版本）；
- 坚持“不绕过客户端协议”；
- 保留并复用客户端 `GuiLogin` 流程。

---

## 14. 结论与下一步

- 若本联调方案可执行且覆盖完整：下一步进入 **P1-05 客户端二开优先级路线图**；
- 若主程序识别仍不确定：新增 **D1-04A ztgame.dat / ztgame.exe 主程序识别验证**；
- 若 C# 登录器代码已具备：进入 **C# 登录器源码级改造方案**。
