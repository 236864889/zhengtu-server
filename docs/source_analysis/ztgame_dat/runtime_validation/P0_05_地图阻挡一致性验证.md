# P0-05 客户端与服务端地图阻挡一致性验证

## 1. 验证目标

本阶段用于静态确认以下一致性风险：

- 地图 ID 是否双端一致；
- 坐标体系（格子/像素/屏幕）是否双端一致；
- 阻挡/可走区域判定是否双端一致；
- 传送点与目标坐标是否双端一致；
- 移动请求是否由服务端最终裁决。

## 4. 地图资源读取链路

### 4.1 结论摘要

- 引擎层通过 `data\*.pak` 自动发现并挂载资源包（不限于单一包名）；
- `datas.pak` 明确参与大量资源读取（文字、过滤词等）；
- `map.pak` 在当前源码中未检索到明确硬编码字符串，但按 `*.pak` 扫描机制可被统一加载；
- 地图切换/坐标处理主要由 `GameScene + MapScene` 体系驱动。

### 4.2 资源读取表

| 资源 | 读取函数 | 所在文件 | 用途 | 缺失后果 |
|---|---|---|---|---|
| `data\*.pak` | 包扫描初始化逻辑 | `engine/source/FilePackHelper.cpp` | 构建统一资源索引 | 地图/界面/特效等资源无法定位 |
| `datas.pak` | `OpenPackFileForRead` | `engine/source/BmpTextout.cpp`, `engine/source/PhraseFilter.cpp`, `engine/source/Spell.cpp` | 文本/词库/字形等基础资源 | UI文本/过滤/拼写资源异常 |
| 地图场景资源 | 由 Map/Scene 模块调度 | `Client/GameScene*`, `Magic/MapScene*` | 地图加载与切换 | 黑图、场景对象错位、无法行走 |

## 5. 客户端阻挡 / 可走区域判定

基于现有静态可见信息：

1. 客户端存在坐标多体系转换（格子/像素/屏幕），由 `MapScene` 提供核心转换能力；
2. 客户端存在 Path 模块，说明“点击移动 -> 路径生成 -> 表现移动”在本地有预判；
3. MiniMap 参与坐标投影和导航交互，若坐标换算不一致会直接影响点击定位；
4. 客户端移动更偏“可视预判 + 表现”，最终是否可达仍应以服务端判定为准（MMO 常规模式）。

可见风险点：

- 若客户端阻挡表版本老旧，可能出现本地可走/服务端不可走；
- 若客户端 Path 规则严于服务端，可能出现本地不可走/服务端可走；
- 若小地图与主场景坐标缩放不一致，点击点会系统性偏移。

## 6. 服务端地图判定可见性

**当前仓库未发现完整服务端地图判定源码**（未见 `ScenesServer/SceneManager/SceneUser` 等路径）。  
因此本阶段无法完整静态确认：

- 服务端地图阻挡数据结构；
- 服务端移动请求校验流程；
- 服务端传送点校验细节；
- 服务端非法坐标拒绝策略。

结论：本项需后续补齐服务端源码或通过运行时联调验证。

## 7. 双端一致性风险

| 风险 | 客户端表现 | 服务端表现 | 玩家看到的现象 | 优先级 |
|---|---|---|---|---|
| 客户端可走、服务端不可走 | 本地路径可生成并前进 | 服务端拒绝位置更新 | 回弹、卡步、瞬移回原点 | P0 |
| 客户端不可走、服务端可走 | 本地不出路径 | 服务端本可接受 | 看起来“点不动”，但他人可到达 | P1 |
| 地图 ID 错位 | 加载了错误地图资源 | 服务端在另一地图 | 坐标同步错乱、对象错位 | P0 |
| 传送点错位 | 入口点触发但目标错 | 服务端按另一目标传送 | 传送到异常坐标/地图 | P0 |
| 坐标缩放不同 | 小地图点击偏移 | 服务端按真实坐标处理 | 路径偏、点A走B | P1 |
| 地图边界不同 | 客户端允许越界尝试 | 服务端边界拦截 | 贴墙抖动/持续回弹 | P1 |
| 阻挡数据版本不同 | 本地障碍与真实不同步 | 服务端按新版本判定 | 穿模失败、看似“空气墙” | P0 |

## 8. 地图 / 坐标 / 传送点必须一致字段

必须双端一致：

- 地图 ID；
- 地图名称（用于配置映射时）；
- 地图宽高；
- 格子大小（Grid size）；
- 坐标单位（格/像素/逻辑单位）；
- 阻挡层数据；
- 传送点 ID；
- 传送目标地图 ID；
- 传送目标 X/Y；
- 出生点坐标；
- NPC/怪物刷新点坐标。

---

## 9. Unity / UE5 重构影响

- 旧地图视觉资源不一定可直接复用，需要转格式；
- 阻挡数据可转为 NavMesh 或网格阻挡层，但必须保留与服务端一致的逻辑坐标；
- 新客户端可重做视觉地图，但不能改动逻辑 ID/坐标语义；
- 传送点和阻挡层应先导出为中间格式（JSON/二进制表），再适配新引擎；
- 协议中的地图/坐标字段与表 ID 映射必须保持兼容。
