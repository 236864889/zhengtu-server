## 3. UI 系统总览

按源码实际主链路：

`CGameAppation::InitInstance`  
-> `FindResource` 预加载多组 GL 图集  
-> `GetGameGuiManager()->InitCreate()` / `Init()`  
-> 游戏流程中 `Game.cpp` 批量 `AddGui*` 创建各模块界面  
-> 各界面 `OnGuiEvent` 处理按钮与交互  
-> 通过 `SEND_USER_CMD` / `GetClient()->PushCommand` 发协议，或只做本地刷新。

说明：UI 初始化分两层——应用启动层做图集与GUI系统准备，游戏状态层按功能逐步创建具体界面。

## 5. 登录界面链路

- 登录页图素依赖 `login.gl` 与 `logo.gl`；`GuiLogin.cpp` 中 `CLogoAni` 直接使用 `data\logo.gl` 多帧动画；
- UI系统启动后，`Game.cpp` 调 `AddGuiLogin()` 创建登录界面；
- 登录态转换时会反复回到 `AddGuiLogin()`（失败回退/退出选角）；
- 登录按钮最终通过协议发送流程进入网络层（项目中统一使用 `SEND_USER_CMD`/`PushCommand` 宏链）。

`config.ini` 与登录参数的关系已在 P0-01 完成，本阶段不重复展开，仅确认 UI 入口与协议触发位置。

---

## 6. 选角界面链路

- `CGuiSelectCharDialog` 负责角色列表与进入游戏；
- `SetAttrib` 把服务端返回的角色列表填入下拉框；
- `LoginServer()` 在点击“进入游戏”后构造 `stLoginSelectUserCmd` 并 `SEND_USER_CMD(cmd)`；
- `command.h` 定义 `stLoginSelectUserCmd`（`LOGIN_SELECT_USERCMD_PARA=3`，`charNo` 字段）；
- `ExitLogin()` 可退回登录界面并重置客户端连接状态。

备注：本轮静态检索未定位到 `BackUpLoginSelectCmd` 实现，建议在后续 D1-03 动态追踪补齐。

---

## 7. 背包 / 物品 UI 链路

- `CGuiPackage` 通过 `CRoleItem` + `ObjectBase_t` 初始化格子尺寸、类型与定位；
- 背包背景根据对象ID切换 `interfaces1.gl` 指定帧；
- `m_iTableType=OBJECTCELLTYPE_PACKAGE`，支撑拖拽/放置语义；
- `OnGuiEvent` 处理按钮事件（如关闭），复杂道具操作由表格控件与全局物品流程触发协议。

结论：背包UI是“图集 + 表格控件 + 物品对象模型”三层耦合。

---

## 8. 装备 / 角色属性 UI 链路

- `CGuiEquip` 在 `OnCreate` 中为各装备位绑定 `CGuiTable`（头、项链、戒指、武器等）；
- 每个槽位标记 `OBJECTCELLTYPE_EQUIP` + `m_EquipPosition`；
- 渲染阶段从主角对象读取属性/名称并绘制；
- 装备穿脱操作不只是本地UI变化，最终需服务端返回属性/物品状态同步。

结论：装备UI改动若触及槽位语义或穿脱流程，属于高风险协议联动区。

---

## 9. 技能 UI 链路

沿用 P1-02 结论，补充 UI 侧关键点：

- `GuiSkillTree` 构建技能按钮时读取 `SkillBase_t.dwIcon`；
- 通过 `SetBitmap(stResourceLocation("data\\icons.gl",1,dwIcon))` 映射技能图标；
- 技能点、冷却遮罩、可用状态由 `RoleSkill + MainCharacter` 数据驱动；
- 技能点击、拖拽到快捷栏最终会触发技能选择/释放命令流程。

---

## 10. 聊天 / 任务 / 小地图 UI 链路

- 聊天：`Game.cpp` 中 `AddChatSelect/AddChatOutput/AddSysChat` 创建聊天相关界面；聊天消息显示多为客户端展示，但“发送聊天”必然走协议。
- 任务：`AddTaskDialog` 创建任务面板；`Game.cpp` 中多处分支刷新任务内容与状态。
- 小地图：`AddMiniMap` 创建；`GuiMiniMap.cpp` 支持 Lua 绑定与交互入口（开关、跳转、私聊等）；小地图点击/寻路类动作会触发场景/网络逻辑。

分类：
- 只显示型：部分文本提示、面板可见性切换；
- 协议参与型：聊天发送、任务交互、地图点击寻路/传送相关动作。

## 11. UI 事件与协议发送

| UI 界面 | 事件函数 | 触发动作 | 协议结构 | 是否服务端参与 |
|---|---|---|---|---|
| 选角界面 | `CGuiSelectCharDialog::LoginServer` | 进入游戏 | `stLoginSelectUserCmd` | 是 |
| 背包界面 | `CGuiPackage::OnGuiEvent` + 表格交互 | 关闭/拖拽/使用道具 | 物品相关 usercmd（由上层流程发） | 是（道具操作） |
| 技能界面 | `GuiSkillTree` 按钮事件 | 学习/选择/释放技能 | 技能相关 usercmd | 是 |
| 聊天界面 | 聊天输入事件（由聊天模块处理） | 发送聊天 | 聊天相关 usercmd | 是 |
| 小地图界面 | 小地图按钮/Lua绑定函数 | 开关/定位/交互 | 部分仅本地，部分场景/网络命令 | 视动作而定 |

说明：项目协议发送模式以 `SEND_USER_CMD` 与 `GetClient()->PushCommand` 为主，不强依赖 `Client_SendCommand` 字面函数名。

## 14. Unity / UE5 重构影响

- UI 页面可按“登录/角色/战斗HUD/背包装备/社交任务”模块重建；
- GL 图集建议离线转换为 Atlas（保留帧索引映射）；
- 控件 ID 与事件语义需保持兼容；
- 与服务端协议绑定的按钮逻辑不可随意改动；
- 建议建立映射表：

`界面 -> 控件 -> 资源(图集帧/XML) -> 触发事件 -> 协议结构 -> 服务端结果`

## 16. 结论与下一步

### 16.1 结论

- UI 初始化入口明确在 `GameAppation::InitInstance`（资源预加载 + GUI管理器初始化）；
- 登录/选角/背包/技能/聊天/小地图入口在 `Game.cpp` 的 `AddGui*`/`Add*` 创建序列与各 `Gui*.cpp` 事件函数；
- UI 资源引用模式为 `FindResource` 预加载 + `stResourceLocation` 运行时按组帧取图；
- 协议联动入口以 `SEND_USER_CMD` / `PushCommand` 为核心。

### 16.2 下一步

- 若 UI 链路已清晰：进入 **P1-04 客户端登录器联动方案**；
- 若 UI 资源映射仍不完整：新增 **D1-03 UI资源动态追踪方案**。
