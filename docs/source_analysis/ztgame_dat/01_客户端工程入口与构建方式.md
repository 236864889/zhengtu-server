# ztgame.dat 客户端工程入口与构建方式

## 1) 工程/构建关键词确认
- 主解为 `ztgame.dat/Client/Client.sln`，主工程为 `Client.vcproj`，并显式依赖 `Engine/EncDec/gui/Magic/Media/Property/xml_parse/zlib/lua/luabind/RenderD3D8/greta` 等子工程，说明客户端构建是“主程序 + 引擎 + 加解密 + 资源/脚本库”的聚合构建。  
- `MakeExe/MakeExe.sln + MakeExe.vcproj` 为独立 MFC 工具链工程，非主游戏逻辑入口。  
- 仓内存在 `removejunk.bat`、`folder-alias.json` 的引用说明（README 中提及），可视为清理/目录映射辅助文件，不在主入口链路。

## 2) 客户端入口点
- 代码层主入口在 `Client/GameAppation.cpp`：
  - `WinMain(...)` 最终 `return main(0,NULL);`，实际转到引擎/框架 `main`。
  - `CGameAppation::InitInstance()` 完成客户端实例化、配置加载、UI/资源初始化、窗口显示。
- `MakeExe` 侧入口是标准 `CWinApp::InitInstance()`（`CMakeExeApp`），仅用于工具程序，不是游戏客户端运行入口。

## 3) UI 消息循环与主循环关系
- `CGameAppation::MsgProc(...)` 统一接收 Windows 消息，先转给设备层（输入坐标转换、鼠标键盘处理），再分发给光标/声音/UI等系统。
- 该模式表明 UI 交互通过消息泵驱动；游戏主逻辑与渲染帧循环在 Appation/Engine 框架层执行，`MsgProc` 作为输入与界面事件入口。

## 4) 结论（入口与构建）
- **客户端真正入口**：`Client/GameAppation.cpp::WinMain -> main -> CGameAppation::InitInstance`。  
- **构建主入口**：`Client/Client.sln`。  
- **工具工程**：`MakeExe` 独立存在，偏发布/封装流程，不参与在线游戏运行时入口。
