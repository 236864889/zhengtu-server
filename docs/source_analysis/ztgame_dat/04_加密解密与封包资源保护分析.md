# 加密解密与封包资源保护分析（EncDec / 协议 / 资源）

## 1) EncDec 组件与工程关系
- `Client.sln` 显式包含 `EncDec` 工程，说明其为客户端构建依赖之一。
- `Client.cpp` 直接 `#include "../EncDec/include/EncDec.h"`，并在收包线程中调用 RC5/DES 相关方法，证明 EncDec 参与运行时网络数据处理。

## 2) 协议加密链路（登录与会话阶段）
- `Client_MsgThread` 逻辑显示：
  - 登录阶段（`m_bLoginRecv == true`）使用 `RC5_32_decrypt`；
  - 非登录阶段使用 DES（`DES_encrypt1(..., DES_DECRYPT)`）。
- 因此协议层至少存在“登录密钥阶段 + 会话密钥阶段”的分层加密策略。

## 3) 压缩与封包
- 包头高位标记：
  - `PACKET_FLAG_ENC`（加密）
  - `PACKET_FLAG_ZIP`（压缩）
- 当存在 ZIP 标记时调用 zlib `uncompress` 解压，再进入上层命令解析。
- 结论：协议包为“长度/标记 +（可选压缩）+（可选加密）”的复合封装。

## 4) 与服务端 base/EncDec 的关联
- 服务端 `ztgame/base` 存在 `zSocket.h`，同样声明 `packetPack/packetUnpack`、`CEncrypt`、DES key 设置等机制。
- `zType.h` 中 `t_NewLoginSession` 含 `des_key` 字段，表明会话密钥可由登录态下发并在后续通信中启用。
- 因此客户端 EncDec 与服务端 base 网络层是同构设计，存在明确协议耦合。

## 5) 是否参与 PAK/DAT 资源处理
- 资源侧在 `engine` 可见 `PackAggregate/PackSubStream/FilePackHelper`：
  - `PackAggregate` 支持 `flagEncrypt/flagCompress/CRC`；
  - `PackSubStream` 根据标记执行加解密/解压读取。
- `GameAppation::LoadFaceInfo()` 示例通过 `OpenPackFileForRead("data\\datas.pak", "datas\\face.xml")` 读取资源，说明 DAT/PAK 资源确实走封包流。
- 结论：Enc/Dec 思路不仅用于网络协议，也延伸到资源包保护（至少支持加密标记与 CRC 校验）。
