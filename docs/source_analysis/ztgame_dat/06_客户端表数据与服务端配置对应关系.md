# 客户端表数据与服务端配置对应关系（Property / TBL / XML）

## 1. 客户端表数据结构
- 客户端 `Client/table.h` 定义并缓存大量基础表结构：`ObjectBase_t/NpcBase_t/SkillBase_t/SkillLevelBase_t` 等，并提供 `GetObjectBase/GetNpcBase/GetSkillBase` 查询入口。
- 运行时对象（`Item/Npc/Role/Monster`）通过这些表做静态属性解析（图标、类型、等级需求、技能参数等）。

## 2. 与服务端 TBL/XML 对应关系
- 服务端 `base/zDatabase.h` 存在 `ObjectBase` 等基础结构，字段语义与客户端 ObjectBase 系列同源，说明策划表是“同一份逻辑数据的双端投影”。
- 客户端显示侧常读取 XML（示例 `datas\\face.xml`），而核心数值更偏 TBL/二进制表载入；服务端则在 base/DB 层维护同类定义用于计算与校验。

## 3. 物品/NPC/技能/装备/称号图片配置入口
- 物品/装备图：`items.gl` + `ObjectBase` 图像字段（客户端经 `GetItemPicLocation`、角色装备界面渲染）。
- NPC 图像：`NpcBase_t`（如 `GetNpcImageID/GetNpcPic` 一类查询）。
- 技能表现：`SkillBase/SkillLevelBase` + `Magic` 模块资源。
- 称号/头衔：UI 显示由角色属性/社交面板驱动，资源仍通过 GL/PAK 路径映射。

## 4. 哪些数据必须双端一致
- **必须一致（强约束）**：
  - 协议命令号/字段布局（`base/Command.h` 与客户端构包/解包代码）。
  - 核心战斗与属性参数（技能ID、数值、目标类型、装备属性字段）。
  - 物品/NPC/技能主键ID 与基础分类（避免客户端显示与服务端判定错位）。
- **可部分不一致（弱约束）**：
  - 纯展示文案、部分 UI 本地化文本。
  - 不参与服务端校验的客户端演出参数（需谨慎，仍可能影响观感一致性）。

## 5. 变更建议
- 改技能/装备/NPC时，至少做“三联改动”：`服务端表` + `客户端表/资源` + `协议兼容检查`。
- 对称号、坐骑、外观类改动，优先核对 ObjectBase/NpcBase 的图片字段与 `items.gl`/相关包是否同步更新。
