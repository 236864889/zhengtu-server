# 03_服务端启动顺序（v0.2）

## 1) 仓库脚本启动顺序（事实）
### `start.sh`
`SuperServer -> RecordServer -> BillServer -> MiniServer -> SessionServer -> ScenesServer -> GatewayServer`。
- `FLServer` 在该脚本中被注释。

### `start1.sh`
`SuperServer -> FLServer -> RecordServer -> BillServer -> MiniServer -> SessionServer -> ScenesServer -> GatewayServer`。

## 2) 实测/推荐启动顺序（用于运行验证）
推荐采用 `start1.sh` 的顺序：
1. `SuperServer`
2. `FLServer`
3. `RecordServer`
4. `BillServer`
5. `MiniServer`
6. `SessionServer`
7. `ScenesServer`
8. `GatewayServer`

说明：该顺序与服务间 `*Client*` 依赖命名更一致，便于减少上游未就绪导致的连接失败（端口与连接重试策略待确认）。

## 3) `stop.sh` 停止逻辑
- 通过 `ps aux | grep ./<Server> | awk '{print $2}'` 获取 PID。
- 使用 `kill -9` 强制停止：`SuperServer`、`FLServer`、`roleRegServer`、`InfoServer`。
- 风险：强制 kill 可能导致日志未落盘、会话未清理（待确认）。

## 4) 启动失败优先检查项
1. 二进制是否存在且可执行（例如 `ScenesServer/ScenesServer`）。
2. 基础静态库是否完整（`libzebra.a`、`libencdec.a`、`libcrypto.a`、`liblua.a`、`libluabind.a`）。
3. 配置文件路径与权限（`Config/*.xml`、根目录 `*.xml`、`quest/`、`newquest/`）。
4. 数据库连通性（`mysql_config` 相关依赖、连接参数来源待确认）。
5. 日志目录与权限（脚本会清理 `/tmp/*.log*`）。
6. 启动顺序是否满足上游服务先启动。
